会话与上下文

Agent 里的「一次对话」，和你以为的很不一样。这一页解释了为什么它有时候很快、有时候很费钱、有时候聊到一半突然变笨——以及你该怎么应对。

一次「回复」背后发生了什么

在聊天框里，你发一句、它回一句，一来一回。在 Agent 里不是这样。

轮次 Turn

你按下回车 → 它一直干到停下来。这整个过程叫一轮。

你以为的「一次对话」，就是一轮。

步骤 Step

一次模型请求，加上它引发的工具执行，等于一个步骤。

一轮里可以有零个步骤，也可以有几十个。

📊
一个实测参考 让它「把这个文件里的 bug 修掉」，通常是 5 到 30 个步骤。每多一个步骤，就多烧一次 token、多花一点钱。

所以 Agent 慢、贵，并不是因为它笨，而是因为它在真的干活。它给你的「回复」其实是一份工作日志，不是一段答案。

这也解释了第一次用它时的困惑：为什么它「想了那么久才回一句话」？因为它在那段时间里发了十几次请求。

上下文：Agent 的办公桌

模型每次只能看到你递给它的一堆文字。这一堆文字叫上下文，里面装着：

  • 系统提示词 —— 它的身份和规矩。你看不见，但它每一轮都在读
  • 工具列表 —— 它能用哪些工具、每个工具怎么用
  • 这几轮的所有对话历史，以及所有工具的输出
  • 你刚发的那句话
📏
它有一个上限 DeepSeek 的上下文窗口是 100 万 token，听起来非常多。但一条命令的输出就能吃掉几千 token——读一个大文件、跑一次测试、贴一份日志，桌面很快就满了。

压缩：桌面满了怎么办

满了之后，Agent 会做一件事：把前面那一大段对话总结成一段摘要，用它替换掉原文，然后接着干。这个过程叫压缩。

好处代价
腾出空间，任务可以继续做下去，不至于半路崩掉 细节丢了。摘要里没写的东西，它就真的再也想不起来了

很多 Agent 支持手动压缩。手动触发比系统在关键时刻自动压缩要好——因为你清楚哪个时间点任务告一段落了，可以安全地丢细节。

⭐
由此得到一条最实用的经验 需要留下来的东西，让 AI 写进文件，不要只留在对话里。

对话会被压缩、会被丢掉；文件不会。这也是为什么 Agent 最好的用法，永远围绕着一个工作目录。

对照一下这两句话的差别：

✗ 「这个结论你自己记着，后面要用。」     ← 压缩一次就没了
✓ 「把这个结论写进 notes.md。」           ← 它记得住一辈子

你会用到的四个会话操作

操作什么时候用
新建 换一件不相关的任务时，一定开新会话。混在一个会话里干三件事：前面的无关内容会干扰它的判断，而且你每一轮都在为那些无关内容付钱。
恢复 关掉电脑，明天接着干，日志还在。这是 Agent 相对聊天框的一个大优势——任务可以跨天。
分叉 从当前这一步复制一份，去试另一种方案，原来的对话完全不动。典型场景：「这个改法我不满意，但我不想丢掉前面聊的东西。」
压缩 主动让它总结并清空前面的内容，腾出空间。典型场景：一个大任务刚做完，准备开始下一个阶段。
🎯
如果这一页只记住一句话 会不会用 AI，很大程度上看你会不会管会话。

管住它的两个开关

Agent 一旦动起来，你很难在中间拦住它。所以大多数工具给了你两个「事前」和「事中」的控制手段。

计划模式：动手之前先给你看方案

开启之后，它只出方案、绝不动手。你看完它写的完整计划，点「同意」，它才开始改文件。

  • 适合：会动到重要文件的重活
  • 不适合：你想让它顺手改个错别字

它管的是「开始之前」。

目标模式：给一个长期目标，它自己接着干

你给一个目标，它自己一轮一轮做下去，不用你每次催。中途你可以暂停、改目标、或者看它卡在哪一步。

  • 适合：一次讲不完、要跑很久的大任务

它管的是「中途不跑丢」。

子代理：派一个干净的分身

让它派一个「分身」去干一件独立的事——查资料、跑一遍测试、审一遍代码。这个分身有自己的上下文，不会污染你的主对话，干完只带回来一个结论。

类比：你不会让同一个人一边写论文、一边跑腿取快递、还一边记着他做过的所有事。

🗂️
这三个概念在哪见 计划模式和目标模式在 DSH 的界面上就是两个开关；子代理在 Claude Code 里对应 CLAUDE_CODE_SUBAGENT_MODEL 那个环境变量——你之前配置的时候已经见过它了。

所以，具体该怎么做

  1. 开工前先想好工作目录

    所有相关材料放进同一个文件夹，让 Agent 在那个文件夹里干活。

  2. 一个任务一个会话

    换任务就新建，别舍不得。

  3. 阶段成果立刻落盘

    每完成一小步，让它把结论写进 notes.md 之类的文件。这样即使压缩了、即使会话丢了，你还能继续。

  4. 大任务先看计划

    用计划模式过一遍方案，比事后收拾烂摊子省事得多。

  5. 觉得它变笨了，就是该开新会话了

    不用怀疑自己。上下文满了就是会变笨，这是机制决定的。
