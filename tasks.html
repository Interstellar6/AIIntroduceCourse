四个练习任务

环境装好了，接下来要真的用一次。四个任务难度递增：前两个是工具基础，后两个是真刀真枪。做完之后，把成果写成一个 Issue 交上来。

🎯
三个任务共同的规则：不许自己写代码、不许自己查资料 你的工作是三件事：把要求说清楚 → 让它做 → 跑一遍看真实结果 → 把真实的问题反馈给它。
看到它卡住时，第一反应不要是自己上手改。你的价值在「说清楚」和「判断对不对」，不在敲代码。

怎么选

没怎么碰过命令行

从任务一和任务二开始。它们是后面所有任务的基础，而且学一次能用很久。

写过一点代码

直接做任务三。你会体验到「一个人带一个团队」的感觉。

不限专业

任务四任何人都能做，也是四个里最能锻炼判断力的。

任务一 · 让 AI 教你用终端

题目

让 AI 当你的终端老师，教会你五个最基本的操作，并且让你明白每一条命令为什么这么设计。

这五个操作是：① 我在哪 ② 这里有什么 ③ 新建一个文件夹 ④ 走进去 ⑤ 新建并查看一个文件。

要求

怎么开始

在 ~/ai-lab 里启动任意一个工具，然后说：

我想学会用终端，但我完全没基础。

请你当我的老师，教会我下面五件事，一件一件来，每教完一件等我确认再继续：
1. 怎么看我现在在哪个目录
2. 怎么看这个目录里有什么
3. 怎么新建一个文件夹
4. 怎么进入这个文件夹
5. 怎么新建一个文件并查看它的内容

每教一个命令，请解释：这条命令的全称是什么、为什么这样命名、
它接受的参数是什么意思。最后出三道小题考我。
💡
为什么要「手敲」 手敲才会打错字，打错才会遇到报错，遇到报错你才会去问它——这一圈下来才是完整的循环。复制粘贴会让你什么也学不到。

验收

在终端里完成五个操作，并交一段 100 字以内的说明：

我原来以为终端是什么，现在觉得它是什么。
🔍
一个你大概会有的发现 cd 是 change directory，ls 是 list，mkdir 是 make directory……命令名基本都是英文单词的缩写。一旦意识到这一点，终端就从「天书」变成了「缩写词典」。

任务二 · 让 AI 教你用 Git

题目

让 AI 当老师，教你用 Git 管住自己的代码，并完成一次真实的「改坏 → 救回来」。

要求

怎么开始

我想学会用 Git，但我完全没基础。

请你当我的老师，先教我五件事，一件一件来，每教完一件等我确认：
1. 怎么把一个普通文件夹变成 Git 仓库
2. 怎么看当前有哪些改动还没提交
3. 怎么把改动提交上去
4. 怎么看提交历史
5. 怎么把文件恢复到之前的状态

每教一个命令，请解释它到底在干什么、为什么要这么设计。

另外我有个问题一直没搞懂：工作区、暂存区、提交
这三个东西为什么要分成三层？直接提交不行吗？

教完之后陪我做个练习：我会故意把我练习目录里的一个文件改坏，
你告诉我怎么用 Git 把它救回来。
🧯
为什么 Git 值得花这个时间 你会经常遇到这种情况：「刚才还能跑的，现在不行了」。没有版本控制，你只能靠记忆和运气猜自己改了什么；有了它，你可以直接看出来，还能一步退回去。
而且——这门课后面所有「让 AI 改你的代码」的场景，Git 就是你的安全网。它改坏了，退回去就行。

验收

三样东西，都要能当场演示：

  • git log 里至少 3 次提交，每次的说明都能看懂
  • 能完整演示一次「改坏 → 用 Git 恢复」
  • 交一段 100 字以内的说明：版本控制到底帮你解决了什么问题
⚠️
一个很多人会犯的错 把 Git 当成「上传代码的工具」——那是 GitHub，不是 Git。
Git 先在你本机管版本，GitHub 只是其中一个放仓库的地方。先在本机练熟，再考虑往上传。

任务三 · 做一个贪吃蛇

题目

做出一个能在你自己电脑上真的跑起来的贪吃蛇。命令行版或图形界面版都可以。

要求

怎么开始

在 snake 文件夹里帮我做一个贪吃蛇小游戏。

要求：
- 用 Python 写（如果我的电脑上没有 Python，先告诉我怎么装）
- 就用命令行界面，不要额外的图形库，依赖越少越好
- 蛇会动、吃到食物变长、撞墙或撞到自己就结束
- 屏幕上要显示当前分数
- 操作说明写在 README.md 里

做完之后告诉我怎么运行它。

验收

当场演示能玩，并且 README 能让别人照着跑起来。

🔁
这个任务的真正考点：反馈循环 蛇跑不动、按键没反应、中文乱码、窗口一闪就没了……这些只有你跑一遍才能发现。
发现之后要做的事只有一件：把完整的报错原样贴回去给它。不要说「还是不行」——那句话里没有任何它能用的信息。

进阶（自愿）

让它加暂停、加速、最高分记录。每加一个功能就开一个新会话，然后感受一下差别。

开新会话时要记得：读一下那个文件夹里的代码，它才知道前面做了什么。这也是为什么「把结论写进文件」很重要。

任务四 · 读懂 Transformer 论文

题目

把《Attention Is All You Need》变成你能用自己的话讲出来的东西。用 AI 当助教，你当学生。

要求

怎么开始

先把论文 PDF 下载到 ~/ai-lab，然后：

这个目录里有一篇论文的 PDF。请你读完它。

然后：
1. 用「讲给大三本科生听」的方式，解释第 3 节（模型架构）
2. 画一个数据流图，说明从输入到输出，数据经过了哪些步骤、
   每一步张量的形状是怎么变的
3. 列出你认为初学者最容易搞混的 5 个术语，各用一句话解释

我读完会问你问题。

验收

交一页 Markdown 笔记 + 3 个术语的解释。

✍️
必须用你自己的话，不许复制它的原文 因为 AI 的解释可以非常流畅，而流畅不等于你懂了。
判断标准很简单：你讲给同学听，他能不能听懂。
🧰
一个很好用的技巧 如果它讲得太抽象，就要求它换一种方式：「用类比重讲一遍」「举一个具体数字的例子」「做成表格对比」。
同一个概念让它换三种方式讲，你对它的理解会比读十遍原文都深。

做任务时会遇到的坑

下面这些症状，每一个背后都有一个具体的原因。

你会遇到的原因 / 怎么办
它说「已完成」，但实际没做完 模型只会产出文字，它的「已完成」也只是一串文字。去看文件到底改了没有——永远用结果验证，不要信它的汇报。
聊到后面它开始忘事、变笨 上下文满了，触发了压缩。任务告一段落就开新会话，把结论写进文件带走。
它卡在同一个错误上反复试 你给的真实信息不够。把完整报错原样贴回去，不要说「还是不行」。
它在错误的目录里干活 启动前先 cd 到目标目录；在对话里也要把路径说清楚。
它一直问你要权限，很烦 那是审批机制在工作，不是 bug。刚上手时多被问几次是好事，熟悉了再放宽。
