## 第一段 · 开场 + vibe coding（0–3 分）

**翻到：先说说 vibe coding**

### 开场白（照念）

> 这门课叫「人工智能导论」，但我不打算从神经元和梯度下降讲起。我们从一个更实际的问题开始：
>
> **你已经在用 AI 了，为什么还是觉得不好用？**
>
> 答案不是「模型不够聪明」。是大多数人只用了它能力的一小部分。这门课就是把漏掉的那部分补上。

### 讲 Karpathy 那个词

> 2025 年 2 月，Karpathy 造了一个词：**vibe coding**——凭感觉写代码。
> 他的原话描述的工作方式是这样的：完全凭感觉往下推，不去细想代码怎么工作；一路点「全部接受」，不再逐行读改动；遇到报错就整段复制粘回去；代码长到自己看不懂了，也懒得回头读。
> 他自己也说得很清楚：**这只适合周末做着玩的小项目。**
>
> 2026 年，这个词被收进了韦氏词典。它已经不是小圈子黑话了。

**停一下，讲它为什么值得知道**

> 但这件事有个真实的好处：**不会写代码的人，第一次能做出真的能跑的软件。** 这个门槛的下降是真的，不是营销。

**然后转折（这是本段的重点）**

> 问题不在「快」，在于**你不知道它为什么能跑**。
>
> 屏幕上这张表，回去自己看，我这里只念一行——
> 你以为「它说完成了」，实际上它只是产出了一句「完成了」的文字。文件可能根本没改，或者改错了地方。
>
> 页面上那张图叫「冒烟成功」：**它坏了，但报告说成功了。** 这是 vibe coding 最典型的失败方式——你只验证了你试过的那一条路径。

**落到学生身上（点名痛点）**

> 这两个麻烦跟你们关系最直接：
> 一是**作业和答辩要你讲清楚**。代码再能跑，说不清为什么这么写，就是没学会。
> 二是**科研要能验证**。糊出来的实验结果，你自己都不敢往论文里放。

### 收尾：说出课程路线图

> 2025 年 10 月，Simon Willison 给光谱的另一端起了个名字：**vibe engineering**。
> 两者的分界线不是「用不用 AI」，是**谁为结果负责**。
>
> 这门课就干一件事：**把你从最左边往右推一点。** 不是让你抛弃 vibe coding，是让你有得选。
>
> 具体是三个转变，页面上有：
> 一、从「它说完成了」到「我知道它真的完成了」——学会验证；
> 二、从「凭感觉让它改」到「先看方案再放权」——学会框范围；
> 三、从「一个会话干到底」到「知道什么时候该收尾」。
>
> 下面 20 分钟，我们先把第一个转变的地基打上。

**过渡语**：> 要理解这三件事，先要搞清楚一件事——**你天天在用的那个东西，到底是什么。**

## 第二段 · 模型与 Agent（3–6.5 分）★ 核心

**翻到：模型与 Agent**

> 这一页是今天最重要的一页。听懂了这一页，后面所有工具、所有配置、所有注意事项就都能串起来。

### 先立一个对比（指着页面左右两列）

> 绝大多数人对 AI 的使用，停在左边这一列：
> 问它问题、复制答案；它说错了，你重新问一遍；它说「你可以这样删除文件」，然后**你自己去删**；用完关掉网页，一切归零。
>
> **你在搬运信息。**
>
> 右边这一列：给它一个目标，不是一句话；它自己去读文件、跑命令、看报错；报错了它自己改，改完自己再试一次；干完给你，还留有完整记录。
>
> **你在派活。**
>
> 差别不在于模型有多聪明，**在于它能不能动手，以及动完手之后能不能看到后果。**

**举个现场例子**

> 你说「帮我看看这段代码为什么报错」。在聊天框里：你复制代码 → 它猜 → 给你新代码 → 你粘贴 → 跑 → 又报错 → 你再复制报错……来回好几轮。
> 在 Agent 里：它自己打开文件、自己跑、自己看到完整报错、自己改、自己再跑。**你一次都没搬。**

### 把「模型」这个词收窄（这是关键一步）

> 现在把「模型」的定义收窄。一个语言模型的全部工作就是——
>
> **输入一段文字 → 算出下一个字 → 再算下一个字 → 停下。**
>
> 这就是一次 API 调用的全部内容。没有别的。

**从这句话推出三件事（板书这三个词）**

> **一、它没有记忆。** 你关掉网页，它连你是谁都不知道。「它记得我」这件事，是软件在外面替它把对话存下来、每次重新念给它听的。
> **二、它没有手。** 它唯一的输出是文字。它说「我已经帮你删掉那个文件了」——**其实它什么都没删。它在骗你，而且不是故意的。**
> **三、它是一次性的。** 你问、它答、这次调用就结束了。想让它在中间停下来看一眼结果再决定下一步？它自己做不到。

> 页面上那张「各家模型的拟人化形象」图，看个热闹就行。真正的区别不在性格，**在能力、价格和接口**。

### Agent 是什么（写出这个等式）

> **Agent = 模型 + 循环 + 工具 + 持久日志**
>
> 注意：**Agent 不是一个更强的模型。** 它是给这个模型配上了一套外部机制。

**四样东西，各讲一句**

> **循环**——模型说完不算完。它说「我要读 a.py」，程序真的去读，把内容塞回去，再问它一次。转很多圈，直到它不再需要工具。
> **工具**——读写文件、跑终端命令、上网搜索、跑代码。模型只负责「说要用哪个」，**真正执行的是外面的程序**。
> **日志**——每一步都写进一份只追加的记录。所以它可以恢复、可以分叉、可以事后追查它到底干了什么。
> **闸门**——因为它能真的动你的电脑，所以必须有沙箱和审批：哪些能碰、哪些要先问你。

### 一张表看清代价（指着表格最后两行）

> 这张表我不全念，只看最后两行：
> **一次交互的代价**——模型是 1 次 API 调用，Agent 可能是几十次调用加几十条命令。
> **风险**——模型说错话，Agent **真的删错文件、真的花错钱**。
>
> 记住这两行。它解释了为什么下一节课我一定要教你看账单，也解释了为什么所有 Agent 都要有审批机制。

### 那你到底该用哪个（防一个常见误区）

> **Agent 不是「更高级的用法」。** 它是一个有成本的工具，用错地方只会更慢更贵。
>
> 出现下面任何一条，你才需要它：**一、任务要碰你的文件；二、任务需要多步试探；三、中间过程太多你不想搬运。**
>
> 这条不是客套。很多人装了一堆 Agent，最后还是回去用聊天框——**因为他们的任务本来就不需要 Agent**，只是听说「这个更强」。

**落到学生身上**

> 对照你们自己的活：
> 整理数据、跑复现实验、管理参考文献——**非常符合**。
> 学会用终端、读懂一篇论文——也能用，但它是**陪练和助教**，不是干活的。
> 「帮我写一段论文」——**不太符合**。写作的中间结果没法自动验证，最终判断只能是你。
>
> 一句话判断标准：**能被跑起来验证的任务，交给 Agent 收益最大；只能靠你判断的任务，它帮不上多少忙。**

**过渡语**：> 好，知道了它是什么。接下来是最实际的问题——**第一句话该怎么说。**

## 第三段 · 怎么跟 Agent 说话（6.5–9.5 分）

**翻到：怎么跟 Agent 说话**

### 先讲它不知道的三件事

> 大部分「它怎么这么笨」的时刻，其实是你漏说了某件事：
> **一、它看不到你的屏幕。** 你在想什么、刚才试过什么、哪个文件相关——它一概不知道。
> **二、它不知道你的「好」是什么标准。** 「优化一下」是快？是短？是省内存？你说不清，它就只能自己挑一个。
> **三、它不知道哪些东西碰了会出事。** 哪个文件不能动、哪个目录里是重要数据——它没有这个常识。

### 给出骨架（板书这四个词，这是本段最该被抄下来的东西）

> **目标 · 位置 · 验收 · 边界**
>
> 页面上有一个可以套用的例子，我念一遍你们感受一下：
>
> > 「data/ 目录下有三个 csv，列的顺序不一样，但表头含义相同。把它们合并成一个 merged.csv，统一列顺序，在报告里告诉我你按什么规则对齐的列。**验收**：merged.csv 的行数应该等于三个文件行数之和。**边界**：不要改 data/ 里的原始文件。」
>
> 对比同一件事的另一种说法：「帮我把这几个 csv 合并一下」。
> 后者也能跑起来。但你会得到：**列对错了你不知道、原始文件被覆盖了、行数少了几十行也没人告诉你。**
>
> **省下的那两行字，要用三轮来回补。**

**重点强调验收**

> 四个里最容易被忽略、也最有用的是**验收**。
> 如果你能说出一条「跑完看到什么就算成功」的命令，**就一定要说出来**。
> 它不只是帮你验收——**它会直接改变它的做法**，因为它知道最后要被检验。

### 反馈的质量决定结果的质量（本页最重要的一节）

> 一句话里尽量包含三样：**我做了什么、我看到了什么、我期望什么。**
>
> 「我按你说的跑了 `python snake.py`」——我做了什么。
> 把**真实的输出或报错整段贴出来**，不要只挑一行——我看到了什么。
> 「我以为会出现游戏画面，结果窗口一闪就没了」——**很多人会漏掉这一句。**
>
> 页面上有张图，一只猫在说「你这吃白饭的」。**这句话和「还是不行」是同一种反馈——只有情绪，没有信息。它除了委屈一下，什么也做不了。**

### 一条最省时间的经验

> 如果它在同一个问题上失败了三轮，**问题多半不在它的实现，而在于你给的要求本身有问题**——可能目标互相冲突、可能前提假设不成立、可能这件事根本做不到。
>
> 这时候继续让它「再试一次」，**只是在烧钱。**
>
> **改需求，比改代码便宜得多。**

**现场送五句话（让学生拍照）**

> 这五句今天下课就能用：
> 1「先别动手，把你的计划列给我看。」
> 2「做完之后跑一遍 X，把输出贴给我。」
> 3「有不确定的地方先问我，不要自己猜。」
> 4「只改这个文件，其他都不要动。」
> 5「说说你为什么这么做。」

**过渡语**：> 说完这一句话，接下来是——**一次对话到底是怎么进行的。**

## 第四段 · 会话与上下文（9.5–12 分）

**翻到：会话与上下文**

> 这一页回答一个你一定会遇到的问题：**为什么它聊到一半突然变笨了。**

### 先纠正一个预期

> 在聊天框里，你发一句、它回一句。**在 Agent 里不是这样。**
>
> **轮次（Turn）**：你按下回车 → 它一直干到停下来。
> **步骤（Step）**：一次模型请求，加上它引发的工具执行。
> **一轮里可以有零个步骤，也可以有几十个。**
>
> 所以 Agent 慢、贵，**不是因为它笨，是因为它在真的干活**。它给你的「回复」其实是一份**工作日志**，不是一段答案。
>
> 这也解释了第一次用时的困惑：为什么它「想了那么久才回一句话」？因为它在那段时间里发了十几次请求。

### 桌面比喻（这是全页最好用的一个比喻）

> 模型每次只能看到你递给它的一堆文字，这叫**上下文**。你可以把它想成**它的办公桌**。
> 桌上放着：系统提示词（它的身份和规矩，你看不见）、工具列表、这几轮所有对话历史和工具输出、还有你刚说的那句话。
>
> **桌子满了怎么办？** 它会把前面那一大段对话**总结成一段摘要**，替换掉原文，然后接着干。这个过程叫**压缩**。
>
> 关键是这一句：**摘要里没写的东西，它就真的再也想不起来了。**

**指着那张「deep sleep」的图**

> 上下文快满的时候，它就是这个表情。**不是它变笨了，是它的桌面快放不下了。**

### 给出最实用的一条动作

> 对照这两句话的差别：
> ✗ 「这个结论你自己记着，后面要用。」← **压缩一次就没了。**
> ✓ 「把这个结论写进 notes.md。」← **它记得住一辈子。**
>
> **所以：阶段成果立刻落盘。** 这是今天最实用的一条操作。

### 四个会话操作 + 两个开关

> 四个操作：**新建**（换任务就新建，别舍不得）、**恢复**（关掉电脑明天接着干，日志还在）、**分叉**（从这一步复制一份去试另一种方案）、**压缩**（主动总结，腾空间）。
>
> 两个开关也要知道：
> **计划模式**——动手之前先给你看方案，它管的是「开始之前」。
> **目标模式**——给一个长期目标，它自己一轮一轮做下去，它管的是「中途不跑丢」。
>
> 还有**子代理**：派一个干净的分身去干独立的事，干完只带回来一个结论，不污染你的主对话。

**这一页的落点**

> 如果这一页只记住一句话：**会不会用 AI，很大程度上看你会不会管会话。**
>
> 判断信号很简单：**觉得它变笨了，就是该开新会话了**，不用怀疑自己。

**过渡语**：> 到这里为止，我们讲的都是「它是什么」。接下来三页抬高一层——**那个循环里的每一步，到底该怎么组织。**

## 第五段 · 三种经典范式（12–14.5 分）

**翻到：三种经典范式**

> 这一页听起来最「理论」，但你会**立刻在软件界面上撞见它们**。我只讲三个名字和一句话，你们记住形状就行。

**指着那三张形状图**

> **ReAct**：边想边做，每一步都看真实的观察结果。形状是**一圈一圈往下走**。
> **Plan-and-Solve**：先出完整计划，再逐步执行。形状是**一条直线**。
> **Reflection**：先做出来，再批判，再改。形状是**先在原地打磨再交**。
>
> 提出者分别是 Yao 等 2022、Wang 等 2023、Shinn 等 2023——不用背，知道它们是三篇正式论文就行。

**为什么先讲这个（给出钩子）**

> 这三种范式回答的其实是同一个问题：**Agent 循环里的每一步该怎么组织。**
> 它们不是互斥的。真实产品里往往是组合使用。

**直接映射到你们马上要装的东西（这张表最有价值）**

> 看这张表，这是本页的落点：
> 你在软件里看到的「**边做边看报错、自己改**」——那就是 ReAct，几乎所有 Agent 工具的默认行为。
> **计划模式**：先出方案给你批，批了才动手——那是 Plan-and-Solve 的产品化形态。
> **目标模式**：给个长期目标，它自己一轮轮做——Plan-and-Solve 的长期版本。
> **Claude Code 派子代理去审一遍代码、跑一遍测试**——那就是 Reflection 的工程化形态。
>
> 所以以后你看到一个 Agent 工具的新功能，可以问自己一句：**它其实是这三种里的哪一种？**

**过渡语**：> 现在把这三样放回那个循环里。下一页是今天最抽象、也最值钱的一部分。

## 第六段 · Agent 循环（14.5–18 分）★ 全课最值钱

**翻到：Agent 循环**

> 如果这门课你只记住一个东西，**记住这个五步循环。**

### 讲那五步（指着流程图，一步一步走）

> ① **组装上下文**——把系统提示词、工具表、历史，打包成一大段文字。
> ② **请求模型**——一次 API 调用。
> ③ **模型回答**——它给最终答案？还是要调工具？
> ④ **执行工具**——**真去读文件、真去跑命令。**
> ⑤ **结果写回**——变成下一步的上下文。
>
> 然后**回到第 1 步，重新请求模型**——一直转到第 3 步不再需要工具为止。
>
> 整个 Agent 就是这五步在转圈。

### 两个关键点（这是全课的核心洞察）

> **关键点一：模型是无状态的，记忆住在循环里。**
> 上一页说模型没有记忆。那 Agent 为什么能记住前面做过什么？
> **因为循环每次都把完整的历史重新递给它。** 第 ① 步做的就是这个。
> 所以「记忆」这个能力，**不属于模型，属于循环**。这也解释了为什么上下文会满、为什么需要压缩——因为每次都要把全部历史重发一遍。
>
> **关键点二：第 ④ 步才是真本事。**
> 模型只会「说要读那个文件」。**真的去读、把真实内容喂回去的，是循环。**
>
> 没有第 ④ 步：「它说你应该先看看 config.py 里写了什么」← 还是那个只会打字的模型。
> 有第 ④ 步：「它自己打开 config.py，看到真实内容，发现端口写错了，改掉」← **这才是 Agent。**

### Loop Engineering：难的是四件事

> 「写一个循环」本身不难，几十行代码就能写。难的是这四件事：
> **一、上下文里放什么？** 放多了它糊涂，放少了它瞎猜。
> **二、怎么防止它跑偏？** 权力给太少它干不动，**给太多它敢删你的库**。
> **三、什么时候该停？** 不会停的循环，**就是一个烧钱的循环**。
> **四、出错了怎么办？** 重试？换模型？还是把真实的报错原样喂回去让它自己修？
>
> 把第四件事展开一句：有些工具只把「命令失败了」这句话告诉模型，**这时候模型只能靠猜**。而把完整报错喂回去的工具，它往往一次就改对了。

**指着那张「我们居然在互相等待？！」的图**

> 顺便说：**死循环不一定是它一直转，也可能是它和你谁都没动。** 这就是「什么时候该停」要解决的问题。

### 落到底层原则（板书这一句）

> **让模型每一步都能看到上一步的真实结果。**
> 不是你的转述，是**原始的文件内容、原始的报错、原始的测试输出。**

### 收在这一句上

> **模型是买来的，循环是设计出来的。**
>
> 模型的智力是别人训练好的，你只能选，不能改。但循环里的每一个决策——放什么进上下文、给多少权力、什么时候停、怎么处理错误——**全都是可以设计的**。
>
> 这就是为什么 2024 到 2026 年出现了这么多 Agent 工具：**它们常常用的是同一个模型，差别几乎全在循环和它外面那一层。**

**给一个课后作业式的要求**

> 装好工具之后，**建议你故意展开一次它的步骤记录看一遍**。看着这五步真实地转起来，比读十页文档都管用。

**过渡语**：> 既然差别在循环外面那一层——**那一层叫什么？**

## 第七段 · Harness（18–20.5 分）

**翻到：Harness：模型怎么变成产品**

> 你们一定有过这个感觉：**同一个模型，装在不同软件里，能力差很多。** 这不是错觉。

### 先讲这个词

> harness 的原意是**马具**——笼头、缰绳、鞍、车辕。
> **马有力量，但没有马具，你既坐不上去，也控制不了方向。**
>
> 在 AI 里，harness 指的是「把模型包装成一个能干活的产品」所需要的**那一整套工程**。
> 注意：**它不是一个具体软件的名字，而是一类东西的统称。** Claude Code 是 harness，Codex 是 harness，DeepSeek Harness 也是 harness。

**快速念一遍这一整套包括什么**（不要展开，指着一屏带过）

> 模型适配、Agent 循环、工具与执行、沙箱与审批、会话与日志、上下文管理、界面、配置与插件。
> 其中「Agent 循环」就是上一页讲的那五步——**它归 harness 管。**

### 四层关系（给出这张层次图）

> **模型**决定它有多聪明——这是别人训练好的，你只能选，不能改。
> **Harness**决定它能干多少活、以及会不会闯祸——**这是同一个模型在不同工具里表现不同的真正原因。**
>
> 所以以后遇到「为什么同样是 DeepSeek，在那个软件里好像更强」，答案就在这里。

### 讲 Agent 模式（后面课上会用到）

> 同一个 harness 里，你还能调整「这一次给它装哪些工具、什么规矩」。这个打包好的配置叫**预设**或**模式**。DSH 出厂带了四个：
> **标准**——全套工具，九成任务够用，默认用它。
> **极简**——只有两个工具：持久终端 + 文件编辑器。
> **PTC**——让模型写一段程序来一次性组合很多步操作。
> **创造**——标准能力 + 改造自己的能力。

**这里埋一个钩子，第二节课会回收**

> 为什么必须玩一下**极简模式**？因为它只有两个工具，却几乎什么都能干。
> 原因是——**终端本身就是万能工具**：能读文件、能写文件、能装东西、能跑代码、能上网。
> **给它一个终端，就等于给了它一双手。**
>
> 第二节课装好之后，我会让你开个新会话、切到极简模式、把同样的任务再发一次。**看着两个工具把事做完，你对 Agent 的理解会上一个台阶。**

### 「一切皆插件」

> DSH 的设计准则叫**一切皆插件**：内核被刻意做得极小，只包含几个抽象服务和一个 Agent 循环插件，**其余全部是插件**——模型适配器、每一个工具、会话日志、压缩策略、沙箱审批、网页界面，**甚至那个循环本身**。
>
> 为什么这件事值得知道？它把「选 harness」这个决定的性质说清楚了：**你在选一套可以拆装的东西，而不是在选一个黑盒。**

**过渡语**：> 说到「插件」，你其实今天就能自己写一个——**而且不用会写代码。**

## 第八段 · Skill（20.5–22.5 分）

**翻到：怎么用 Skill**

### 从痛点开场

> 你有没有过这种经历：**同一段要求、同一套步骤，反复粘给 AI 好几次？**
> 「按这个格式输出」「先做 A 再做 B，别跳步」——如果你已经粘了第三次，**那就该写成 skill 了。**

### 一句话讲清是什么

> 一个文件夹，里面放一个 `SKILL.md`，内容就是「遇到这类任务，请按这个流程做」。
> 写完之后有两种触发方式：**你敲 `/名字` 手动调用**，或者**模型自己判断「这活儿正好该用它」的时候自动加载**。

**指着那张「什么常驻上下文、什么不常驻」的图**

> 它比「在对话里多写几句要求」划算在哪，看这张图：
> **模型每一轮都能看到的**，只有 skill 的**名字和一句话描述**；
> **SKILL.md 的正文、附加的参考资料、脚本模板**，都存在你磁盘上——**不用就不加载，不花钱。**
>
> **写多长都行，只要你不用它，它就不占地方。** 这就是它比「一大段写死的提示词」划算的地方。

### 讲结构（一句话 + 一个重点）

> 最简单的形式就是一个文件夹加一个文件。内容分两部分：上面是 `---` 包起来的几行元信息，下面是正文。
>
> **frontmatter 里最重要的就是 `description`。**
> 因为模型只能看到**名字和这句话**，然后靠它决定「这个任务该不该用这个 skill」。
> 写得太笼统（「帮助处理代码」），**它就永远不会被触发**；写得具体（说清什么场景下用），命中率才高。
>
> **描述里写「什么时候用」，比写「它是什么」更重要。**

### 讲放哪里

> 放哪里决定了它在哪些项目里生效：
> **个人**——`~/.claude/skills/` 或 `~/.dsh/skills/`，你这台机器上所有项目都能用。
> **项目**——`项目/.claude/skills/` 或 `项目/.dsh/skills/`，提交进仓库**同组的人也能用**。
> **共享/插件**——随插件分发，装了这个插件的所有人都有。

### 收在「一切皆插件」上

> 回到 Harness 那一页说的「一切皆插件」：**skill 就是你能用到的最日常的那种扩展。**
> 你不需要会写代码、不需要改内核，**只要写一个 Markdown 文件，就改变了这个 Agent 的行为。**
>
> 页面上给了三个你现在就可以写的 skill：读论文的固定流程、跑实验的固定步骤、交作业前的自查清单。**下课回去就写一个。**

**一个提醒**

> 最后提醒一句，页面上也写了：**skill 不是越多越好。** 每个 skill 的名字和描述都常驻在上下文里，装太多会白占地方，也会干扰模型的判断。**只留真正常用的。**

**过渡语**：> 原理部分到这里就结束了。最后两分钟，把名词归位。

## 第九段 · 工具地图 + 收尾（22.5–25 分）

**翻到：工具地图与怎么选**

> 接下来三节课你们会听到五个名字：**Claude Code、Codex、DeepSeek Harness、cc-switch、中转站。**
> 先把最容易搞混的一点说清楚：**这五个里，只有三个是真正装模型的地方，另外两个是配件。**

**指着那张表念归类**

> **Claude Code**——harness。Anthropic 做的，读代码改代码最稳。
> **Codex**——harness。OpenAI 做的，沙箱和权限控制做得最细。
> **DeepSeek Harness**——harness。有网页界面，最适合第一次用。
> **cc-switch**——**配件**。一个开关面板，管理各家供应商配置。
> **中转站**——**配件**。一个卖 API 的中间商。
>
> **后两个本身不产生任何 AI 能力**，只是让「连接」这件事更省事或更便宜。

**打掉一个误解（这个是重点）**

> 「装了 Claude Code，是不是就等于用上了 Claude 模型？」
> **不是。工具和模型是两件事。** Claude Code 是 Anthropic 做的 harness，但只要你把地址改掉，**它调用谁家的模型完全由你决定。**
>
> 这也正是这门课的做法：**用 DeepSeek 的 Key 驱动 Claude Code 和 Codex**，不需要另买 Anthropic 或 OpenAI 的账号。

**收尾（照念）**

> 好，原理部分讲完了。回头看，其实就三句话：
> **第一，模型只会打字，是循环和工具让它真的能干活。**
> **第二，同一个模型装在不同 harness 里差别很大——差别在循环，而循环是可以设计的。**
> **第三，你为结果负责，所以你要会验证、会框范围、会管会话。**
>
> 接下来 20 分钟，我们把它落到手上：**买一个能调用模型的账号，拿到一把钥匙，然后在终端里亲眼看到模型回你一句话。**

## 动手 20 分钟

**翻到：拿到你的 API Key**

> 打开文档站的这一页。**右上角先切到你自己的系统**——Windows 的同学点「Windows」，命令会跟着变。

### 0–2 分 · 布置 + 立两条纪律

> 先立两条规矩，这条比操作本身重要：
>
> **一、Key 不外发。** 不贴到群里、不发给同学、不写进截图和录屏。**别人拿到就能花你的钱。** 万一泄露了，**第一动作是去删掉这个 Key**，不是先改代码。
> **二、从现在开始，所有 AI 相关的活都在一个专门的练习文件夹里干**——今天先建一个，叫 `ai-lab`。**不要一上来就把它指向你的论文、你的代码仓库、你的桌面。**
>
> 没做出来的不要慌，**举手机举手，我过去看**。卡住是正常的，这一步的坑我都写在排错页上了。

### 2–12 分 · 注册 → 实名 → 充值 → 建 Key

**你在讲台上同步做一遍**（用你自己的备用账号，或者只演示到能看到界面为止），边做边说：

> **第一步，注册。** 打开 `platform.deepseek.com`，手机号或邮箱注册。
> 两个坑：部分邮箱域名不能注册，**建议用 Gmail / Outlook / Hotmail / Yahoo**；微信登录不支持海外 IP，Google 登录不支持中国大陆 IP——**卡住就换另一种登录方式**。
>
> **第二步，实名认证。** 在控制台的「个人信息」页，`platform.deepseek.com/profile`，找到「实名认证」。
> 个人认证和企业认证**在使用权益上没有差别**。失败最常见的原因是证件号绑定账号数量超限，或者证件号连续输错被临时锁定。
>
> **第三步，充值。** `platform.deepseek.com/top_up`，支付宝或微信。**充最小的一档就够**——几元到十几元能跑很久。余额**永久有效**，未消费的金额**支持退款**。
>
> **第四步，建 Key。** 左侧「API keys」页，`platform.deepseek.com/api_keys`，点创建，名字就叫 `class1`。
> Key 的格式是 `sk-` 开头的一长串。

**然后让他们把三要素抄进自己的笔记**（这一步别跳过，后面两节课反复用）

> 现在把这个抄到你的笔记文件里，**后面每一个工具都只会问你同样三个问题**：
>
> ```
> base_url : https://api.deepseek.com
> api key  : sk-你的这一长串
> model id : deepseek-flash
> ```

**这里必须停下来强调两个 2026 年的变更**

> 两个你们一定会踩的坑，**网上 2025 年的教程全是错的**：
>
> **① 模型名变了。** 网上教程里的 `deepseek-chat` 和 `deepseek-reasoner`，**已经在 2026 年 7 月 24 日停止使用**。现在只有 `deepseek-flash` 和 `deepseek-v4-pro`。
> **② `base_url` 不要加 `/v1`。** 老教程里的 `https://api.deepseek.com/v1` 已经不在官方文档里了，**官方现在一律写不带 `/v1` 的地址。**
>
> 记住一句话：**新手 90% 的报错，都是 Key / 地址 / 协议这三样没对齐。**

### 12–18 分 · 终端里发出第一次调用

> 打开终端：macOS 是「终端」，Linux 是任意终端，**Windows 是 PowerShell**。
> 把下面命令里的 Key 换成你自己的，**逐行粘贴回车**。

**macOS / Linux**

```bash
export DS_KEY="sk-把这里换成你自己的Key"
curl https://api.deepseek.com/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DS_KEY" \
  -d '{"model":"deepseek-flash","messages":[{"role":"user","content":"用一句话解释什么是Agent"}]}'
```

**Windows PowerShell**

```powershell
$env:DS_KEY="sk-把这里换成你自己的Key"
curl.exe https://api.deepseek.com/chat/completions `
  -H "Content-Type: application/json" `
  -H "Authorization: Bearer $env:DS_KEY" `
  -d '{"model":"deepseek-flash","messages":[{"role":"user","content":"用一句话解释什么是Agent"}]}'
```

> ⚠️ **Windows 上一定要写 `curl.exe`。** PowerShell 里的 `curl` 是另一个内置命令的别名，直接用会报错。另外 PowerShell 的换行符是**反引号** `` ` ``，不是反斜杠。

**他们跑的时候，你在过道里转，重点看这三件事**

1. 有没有人 `sk-` 后面带着空格或换行
2. Windows 用户有没有写成 `curl`
3. 有没有人把 `model` 写成了 `deepseek-chat`

### 18–20 分 · 收尾（这段一定要讲，它是第二节课的引子）

> 跑通的同学，看屏幕上那一大段 JSON。你要找的是两处：
> **`choices[0].message.content`**——模型回你的那句话。
> **`usage`**——这次花了多少 token，也就是**花了多少钱**。
>
> 现在停下来想一件事：**你平时用的那个聊天网页，做的就是这件事**，只不过它把这段 JSON 排版好看了。
> 所谓「AI 对话」，**本质就是一个 HTTP 请求。**

**最后一句话收课**

> 你今天做到的这件事，是所有工具的**共同底座**。第二节课我们要做的，无非是把这段命令换成点几下鼠标——**但底下跑的还是它。**
>
> 下课前把 Key 存好，下节课直接用。

## 附录 A · 卡点对照表（照着念或投屏）

| 报错 / 现象 | 意思 | 怎么办 |
|---|---|---|
| `401` | 认证失败 | Key 复制错了，或者前后多了空格 |
| `402` | 余额不足 | 去充值页充值 |
| `400` / `Model Not Exist` | 模型名不对 | 检查是不是写成了 `deepseek-chat` |
| 连不上 / 超时 | 地址或网络问题 | 检查 `base_url` 有没有多写 `/v1` |
| `429` | 请求太快或并发到上限 | 稍等再试；正常学习用量碰不到 |
| PowerShell 报 `curl` 相关错 | 用了内置别名 | 改成 `curl.exe` |
| PowerShell 命令被截断 | 换行符写错 | 用反引号 `` ` ``，不是反斜杠 |
| 收不到验证码 | 邮箱域名被限 | 换 Gmail / Outlook 这类通用邮箱 |
| 实名认证失败 | 证件号超限或被锁 | 等锁定期结束，或联系客服 |

## 附录 B · 学生可能问的问题（提前准备答案）

**Q：我能不能就用网页版，不买 API？**
> 能，但那是「用法一」。这门课要教的是「用法二」——网页版里你没法让它读你的文件、跑你的实验。而且 API 其实比你想的便宜：**1 块钱大约能买 100 万字的输入，或者 20 万字的输出。**

**Q：会不会很贵？**
> 问问题几乎不花钱，**真正花钱的是让 Agent 跑很长的任务**。另外两件事能再省一半：**错开高峰**（高峰是北京时间周一至周五 9:00–12:00、14:00–18:00，其余时间价格减半），**把稳定的内容放在前面**（缓存命中便宜 50 倍）。

**Q：装 Claude Code 是不是就得买 Claude？**
> 不用。**工具和模型是两件事。** 我们全程用 DeepSeek 的 Key——DeepSeek 官方自己就把 Anthropic 格式的入口开好了（`https://api.deepseek.com/anthropic`）。记住那句话：**协议只是信封，信封可以换，里面的模型才是关键。**
>
> 有个细节挺能说明问题：走这个入口时，模型名会被**自动映射**——写 `claude-opus*` 实际走 `deepseek-v4-pro`，写 `claude-sonnet*` 或 `claude-haiku*` 实际走 `deepseek-flash`。所以哪怕软件界面上还显示着 Claude 的名字，**底下干活的还是 DeepSeek**，账单也按 DeepSeek 的价格算。

**Q：为什么同一个模型要有三个地址？**
> 模型和模型说话时，请求要装进一个「信封」，**不同软件认的信封格式不一样**，所以同一个模型要开三个入口。Claude Code 用 Anthropic 格式，Codex 用 Responses 格式，其他工具用最通用的 OpenAI 格式。**协议跟背后是哪家的模型没有关系。**

**Q：我该装哪个？**
> **第一次用、想省事 → DeepSeek Harness**（网页界面，不用记命令）；**主要写代码跑实验 → Claude Code 或 Codex**；**手头紧 → DeepSeek 官方 API**，国内直连、支付宝付款。**三个都装一遍**，为的是获得一个对比的经验。

**Q：这个 Key 会不会过期？**
> 余额永久有效不会过期，未消费的金额也支持退款。但 **Key 本身要当成密码对待**——泄露了就立刻删掉重建。

## 附录 C · 时间不够时砍哪里

| 剩余时间 | 怎么调整 |
|---|---|
| 正常 | 按时间轴走 |
| 超时 3 分钟 | 「三种经典范式」只讲那张产品映射表（ReAct↔默认行为、计划模式↔Plan-and-Solve、子代理↔Reflection），跳过论文出处 |
| 超时 5 分钟 | Skill 只讲「一个文件夹 + SKILL.md + description 最重要」，跳过放哪里和进阶用法 |
| 超时 8 分钟 | Harness 只讲「马具」比喻 + 「模型决定多聪明，harness 决定能干多少活」这一句，模式列表口头带过（第二节课还会讲） |
| 动手时间被压到 10 分钟 | **只做到第三步（充值）**，建 Key 和终端调用发成课后作业，第二节课开头花 5 分钟检查 |

**任何时候都不要砍的两段**：「模型与 Agent」的「它没有记忆 / 没有手 / 是一次性的」，和「Agent 循环」的第 ④ 步。这两处是全场的地基。

## 附录 D · 板书 / 屏幕要点

```
Agent = 模型 + 循环 + 工具 + 持久日志

① 组装上下文 → ② 请求模型 → ③ 模型回答 → ④ 执行工具 → ⑤ 结果写回
                                          ↑ 第 ④ 步才是真本事

第一句话骨架：目标 · 位置 · 验收 · 边界

三要素：base_url · api key · model id
        https://api.deepseek.com
        sk-...
        deepseek-flash

模型是买来的，循环是设计出来的。
```
