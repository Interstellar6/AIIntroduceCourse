接上 DeepSeek约 3 分钟

Claude Code 说的是「Anthropic 协议」，DeepSeek 正好也提供

macOS / Linux

export ANTHROPIC_BASE_URL=\
  https://api.deepseek.com/anthropic
export ANTHROPIC_AUTH_TOKEN=<你的 Key>
export ANTHROPIC_MODEL=deepseek-flash[1m]
export ANTHROPIC_DEFAULT_OPUS_MODEL=\
  deepseek-flash[1m]
export ANTHROPIC_DEFAULT_SONNET_MODEL=\
  deepseek-flash[1m]
export ANTHROPIC_DEFAULT_HAIKU_MODEL=\
  deepseek-flash
export CLAUDE_CODE_SUBAGENT_MODEL=\
  deepseek-flash
export CLAUDE_CODE_EFFORT_LEVEL=max
export CLAUDE_CODE_AUTO_COMPACT_WINDOW=786432

Windows PowerShell

$env:ANTHROPIC_BASE_URL=\
  "https://api.deepseek.com/anthropic"
$env:ANTHROPIC_AUTH_TOKEN="<你的 Key>"
$env:ANTHROPIC_MODEL="deepseek-flash[1m]"

其余变量同上，把 export A=B 换成 $env:A="B"。

验证

cd ~/ai-lab
claude
# 进去后输入：
/status

能看到 base URL 是 api.deepseek.com，就通了。

这几行是 DeepSeek 官方文档给的配置，不是我们自己凑的。[1m] 是让它用 100 万 token 的超长上下文。

人工智能导论 · 第 3 讲

关键教学点：这几行 export 只对当前这个终端窗口有效，关掉就没了。想永久生效要写进 ~/.zshrc 或 ~/.bashrc。

学生最常问：「为什么是 AUTH_TOKEN 不是 API_KEY？」——第 1 讲的协议那张图：两个变量对应两个不同的请求头（Authorization: Bearer vs x-api-key），用错就到不了网关。拿不准时先用 AUTH_TOKEN。

也可以顺势演示 cc-switch：上节课装的工具，这里正好能一键写进 settings.json。

省事的做法约 1 分钟

不想每次敲这一堆？写进配置文件

手工方式

写进 ~/.claude/settings.json：

{
  "env": {
    "ANTHROPIC_BASE_URL":
      "https://api.deepseek.com/anthropic",
    "ANTHROPIC_AUTH_TOKEN": "sk-xxxx",
    "ANTHROPIC_MODEL": "deepseek-flash[1m]"
  }
}

注意：这里的 env 优先级高于你在终端里 export 的同名变量。

用 cc-switch（上节课装的）

选 DeepSeek 预设 → 填 Key → Enable。它替你写上面这个文件。

Claude Code 是它唯一支持热切换、不用重启的工具。

这就是上节课那个「你可能暂时用不到」的工具，今天开始用得上了。

两种方式都对。区别只是：一个让你理解发生了什么，一个让你省事。建议先用第一种配通，再用第二种。

这个「先手工再自动化」的顺序很重要。学生如果只会点按钮，出问题就完全无从下手。

OpenAI 的终端 Agent，只看 Responses 协议

过渡。

安装约 1.5 分钟

和 Claude Code 几乎一样的流程

安装

# macOS / Linux
curl -fsSL https://chatgpt.com/codex/install.sh | sh

# Windows PowerShell
powershell -ExecutionPolicy ByPass -c \
  "irm https://chatgpt.com/codex/install.ps1 | iex"

# 或者
brew install --cask codex
npm install -g @openai/codex

装完先做一件事

先运行一次 codex 再退出（或者随便跟它说句话）。

目的是让它把 ~/.codex 目录建出来——下一步的配置脚本需要这个目录已经存在。

如果它让你登录 ChatGPT，跳过或者随便登录一下都行，我们马上要把它改成走 DeepSeek。

配置文件的位置要注意：供应商配置必须写在用户级的 ~/.codex/config.toml。写在项目目录里的 .codex/config.toml 会被忽略并警告——这是最常见的坑。

人工智能导论 · 第 3 讲

「先跑一次建目录」这个细节很关键，不说的话下一步脚本会失败。

接上 DeepSeek：官方一键脚本约 2 分钟

Codex 只认 Responses 协议 —— 而 DeepSeek 原生支持

一键配置

# macOS / Linux
bash <(curl -fsSL \
 https://cdn.deepseek.com/api-docs/codex-deepseek-setup.sh)

# Windows PowerShell
irm https://cdn.deepseek.com/api-docs/\
codex-deepseek-setup.ps1 | iex

按菜单选：1 = 用 deepseek-flash（支持图片）  2 = 用 deepseek-v4-pro   9 = 恢复原配置。

首次运行会让你输入 API Key。

它替你做了三件事

  • 备份你原来的 config.toml
  • 写一个 ~/.codex/models.json，告诉 Codex「DeepSeek 这个模型有什么能力」
  • 在 config.toml 里加上 [model_providers.deepseek] 段

它只改必要字段，你原有的其他配置都会保留。选 9 可以随时还原。

顺便复习第 1 讲：Codex 之所以挑供应商，是因为它只支持 Responses 协议。DeepSeek 原生支持，所以能直连。
有些平台只提供 Chat Completions 格式——那种情况下 Codex 用不了，得靠本地代理转换。

这一页把第 1 讲「协议」那张图落到了实处，值得多花一分钟。

同时点明：我们全程没用中转站。这是刻意的——学生第一次配工具，应该走最干净的路。

它给了 Agent 多大的权力约 2 分钟

Codex 的两个安全开关（第 1 讲说的「闸门」）

sandbox_mode：它能碰哪里

read-only只能看，不能改
workspace-write只能在当前工作目录里写
danger-full-access什么都能干（危险）

approval_policy：什么时候要问你

untrusted除了安全只读命令，全都要问
on-request由模型自己决定何时问（默认）
never从不问（只适合自动化场景）

给学生的建议组合

codex --sandbox workspace-write --ask-for-approval on-request

官方的低摩擦组合：允许它在工作目录里干活，但每走一步都先问你。等你信任它了再逐步放宽。

一句话：沙箱管「能碰哪里」，审批管「什么时候停下来问你」。这两个概念在每一个 Agent 工具里都有，只是叫法不同。

人工智能导论 · 第 3 讲

这页信息密度高，但值得讲——它是学生以后用任何 Agent 工具都会遇到的东西。

第三部分

三个任务

自己挑一个开始，做不完可以带回去继续

不用三个都做完。让每个人至少完整做完一个，比三个都浅尝辄止有价值。

建议按基础分：没碰过命令行的 → 任务一；写过一点代码的 → 任务二；任何专业 → 任务三。

任务一题目

让 AI 教你用终端

题目

让 AI 当你的终端老师，教会你五个最基本的操作，并且让你明白每一条命令为什么这么设计。

这五个操作是：① 我在哪  ② 这里有什么  ③ 新建一个文件夹  ④ 走进去  ⑤ 新建并查看一个文件。

要求

  • 每一步都让它解释这条命令在干什么
  • 你必须自己在终端里手敲一遍，不许复制粘贴
  • 最后让它出 3 道小题考你

验收

在终端里完成五个操作 + 交一段一百字以内的说明：
「我原来以为终端是什么，现在觉得它是什么。」

人工智能导论 · 第 3 讲

为什么要「手敲」：手敲才会遇到真正的报错，遇到报错才会去问 AI，问了 AI 才是完整的循环。

「为什么这么设计」这个问题本身就很值——比如为什么 cd 要叫 change directory，为什么 ls 叫 list。命令名都是缩写的英文单词，这个发现对初学者是开窍时刻。

任务二题目

做一个贪吃蛇

题目

用一个会话，做出一个能在你自己电脑上真的跑起来的贪吃蛇。命令行版或图形界面版都可以。

要求

  • 能跑起来，能玩
  • 至少要有：蛇会动、吃到食物变长、撞墙或撞自己就结束、有分数
  • 代码放在一个独立文件夹里
  • 最后让它写一个 README，说明怎么运行
  • 不许自己写代码——你负责说清楚要什么、跑一遍、把问题反馈给它

验收

当场演示能玩 + README 能让别人照着跑起来。

进阶（自愿）：让它加暂停、加速、最高分记录。
每加一个功能就开一个新会话试试，感受一下区别。

人工智能导论 · 第 3 讲

这个任务的隐藏考点是 「反馈循环」：蛇跑不动、按键没反应、中文乱码……这些都必须由学生跑一遍才能发现，然后把真实现象告诉 AI。这正是第 1 讲说的「让模型看到上一步的真实结果」。

如果学生说「它写的跑不起来」——不要帮他改代码，让他把完整报错粘回去。这是本任务唯一的教学动作。

「进阶用新会话」是让他亲身体验会话管理。

任务三题目

读懂 Transformer 论文

题目

把《Attention Is All You Need》变成你能用自己的话讲出来的东西。用 AI 当助教，你当学生。

要求

  • 把论文 PDF 放进工作目录，让它读完
  • 让它用「给大三本科生讲」的方式解释第 3 节（模型架构）
  • 让它画出数据流：从输入到输出，张量的形状怎么变
  • 你自己找出 3 个不懂的术语，逐个问，直到能复述
  • 最后让它出 5 道自测题，你做完让它批改

验收

交一页 Markdown 笔记 + 3 个术语的解释。

必须用你自己的话，不许复制它的原文。

判据很简单：你讲给同学听，他能不能听懂。

人工智能导论 · 第 3 讲

这个任务最难，也最能区分「会用的」和「不会用的」。

关键在最后一条：不许复制原文。因为 AI 的解释可以非常流畅，但流畅不等于你懂了。用自己的话复述，是唯一能验证「真懂」的办法。

提示学生：如果它讲得太抽象，可以要求「用类比」「举个具体例子」「画表格」——同一个概念，让它换三种方式讲。

做任务时会遇到的坑约 2 分钟

这些坑，都是今天讲过的概念

你会遇到的原因 / 怎么办
它说「已完成」，但其实没做完 模型只会产文字。去看文件到底改了没有——用结果验证，不要信它的汇报。
聊到后面它开始忘事、变笨 上下文满了。任务告一段落就开新会话，把结论写进文件带走。
它卡在同一个错误上反复试 你没给它足够的真实信息。把完整报错原样贴回去，别说「它还是不行」。
它在错误的目录里干活 启动前先 cd 到目标目录；会话里也要说清路径。
它一直问你要权限，很烦 这是闸门在工作，不是 bug。熟了之后再放宽 sandbox 设置。
人工智能导论 · 第 3 讲

这一页其实是整门课的知识点复习，只是换成了「你会遇到的症状」的说法。

带着学生做一遍映射：每一条对应第 1 讲哪一页？这比再讲一遍概念有效得多。

课程收尾约 3 分钟

三节课之后，你手上有什么

一个能干活的环境

DeepSeek API + cc-switch + DSH + Claude Code + Codex，全都直连官方，没有一处依赖中转站。

一套判断标准

什么时候该用 Agent、什么时候用聊天框；协议不匹配该查哪三样；钱花在哪里。

一种工作方式

说清要求 → 让它做 → 看真实结果 → 反馈 → 再来一轮。这个循环可以用一辈子。

最后三句话

① 能自己验证的任务，交给它收益最大；只能靠你判断的任务，它帮不上多少忙。  ② 需要留下的东西，让它写进文件，别留在对话里。  ③ 它是工具，不是答案——最终的判断和署名，永远是你的。

人工智能导论 · 第 3 讲

第三句是对一整门课最重要的一句。AI 课很容易上成「工具培训」，最后一定要落回人的判断和责任。

可以补一句现实提醒：课程作业、论文投稿，很多地方已经明确要求声明是否使用 AI 及使用范围。用工具不丢人，隐瞒才是问题。
