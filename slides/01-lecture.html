先定个调约 1.5 分钟

大多数人对 AI 的使用，停在第一个格子里

用法一：把它当搜索引擎

  • 问它问题，复制答案
  • 它说错了，你重新问一遍
  • 它说「你可以这样删除文件」，然后你自己去删
  • 用完关掉网页，一切归零

→ 你在搬运信息。

用法二：把它当同事

  • 给它一个目标，不是一句话
  • 它自己去读文件、跑命令、看报错
  • 报错了它自己改，改完自己再试一次
  • 干完给你，还留有完整记录

→ 你在派活。

差别不在模型有多聪明，而在它能不能动手，以及动完手之后能不能看到后果。

人工智能导论 · 第 1 讲

这一页是全课的引子，要讲出「啊，原来我一直只用了一半」的感觉。

举一个具体例子：「帮我看看我这段代码为什么报错」——在聊天框里，你要复制代码、复制报错、来回三轮。在 Agent 里，它自己打开文件、自己跑一遍、自己看到真报错。这个差距就是整堂课。

第一部分

模型 与 Agent

一个是「会说话的」，一个是「会干活的」

过渡 5 秒，直接进。

模型是什么约 1.5 分钟

模型：一个只会「接着往下写」的函数

输入一段文字  →  算出下一个字  →  再算下一个字  →  ……  →  停下

这就是一次 API 调用的全部内容。没有别的。

它没有记忆

你关掉网页，它连你是谁都不知道。
「它记得我」是软件在外面替它把对话存下来、每次重新念给它听。

它没有手

它唯一的输出是文字。
它说「我已经帮你删掉那个文件了」——其实它什么都没删，它在骗你。

它是一次性的

你问 → 它答 → 这次调用结束。
想让它在中间停下来、看一眼结果、再决定下一步？
它自己做不到，需要外面的程序帮它做。

所以：单靠模型，它只能「告诉你该怎么做」。告诉和做到之间，隔着今天剩下的所有内容。

人工智能导论 · 第 1 讲

重点讲「它在骗你」这条。很多同学被 AI 说「已完成」骗过。根因就是：模型只会产文字，它产出的「已完成」也只是一串文字。

可以说：模型是一台只会打字的机器，它打的字恰好经常是对的。

Agent 是什么约 2 分钟

Agent：给这个模型配上循环、手、和记忆

Agent = 模型 + 循环 + 工具 + 持久日志

1循环

模型说完不算完。如果它说「我要读 a.py」，程序真的去读，把内容塞回去，再问它一次。转很多圈，直到它不再要工具。

2工具

读写文件、执行终端命令、上网搜索、跑代码、派分身。
模型只会「说要用」，真正执行的是外面的程序。

3日志

每一步都写进一份只追加的记录。
所以它可以恢复、可以分叉、可以事后追查它到底干了什么。

4闸门

因为它能真的动你的电脑，所以必须有沙箱和审批：
哪些能碰、哪些要先问你。

结果：它从「回答问题的」变成了「干活的」。

人工智能导论 · 第 1 讲

「闸门」这一项不是可有可无，是 Agent 能存在的前提。补一句：没有闸门的 Agent 不叫 Agent，叫定时炸弹。

如果时间紧，这页讲 4 个词就够：循环、手、记忆、闸门。

不要逐行念。指着最后两行讲：Agent 的代价是「更贵」和「真的会闯祸」，这就是为什么它需要审批。

那你到底该用哪个约 1.5 分钟

出现下面任何一条，你才需要 Agent

① 任务要碰你的文件

改代码、整理几十个 Excel、批量重命名、跑你的实验脚本。

② 任务需要多步试探

「跑一下，报错了，改一改，再跑」——需要它自己看到结果再决定下一步。

③ 中间过程太多，你不想搬运

几十个文件的输出、几万行日志，你不可能复制粘贴给聊天框。

一条都不满足？那就别折腾

「解释一下这个概念」「帮我想三个标题」——用聊天网页更快、更便宜。装工具是有成本的：要花钱、要配置、它还可能改错你的文件。工具是给「干活」用的，不是给「聊天」用的。

人工智能导论 · 第 1 讲

这一页是防止学生「为了用而用」。很多人装了一堆 Agent，最后还是回去用聊天框——因为他们的任务本来就不需要 Agent。

补一句实际经验：写论文的时候，让 Agent 帮你管理参考文献、整理实验数据、跑通复现代码，比让它「帮你写一段话」有价值得多。

第二部分

会话模式

Agent 的「一次对话」，和你以为的很不一样

过渡。

一次「回复」里发生了什么约 1.5 分钟

轮次（Turn）与步骤（Step）

轮次 Turn

你按下回车 → 它一直干到停下来。
这整个过程叫一轮。

你以为的「一次对话」，就是一轮。

步骤 Step

一次模型请求 + 它引发的工具执行 = 一个步骤。
一轮里可以有 0 个，也可以有几十个步骤。

每多一个步骤，就多烧一次 token、多花一点钱。

实测参考：让它「把这个文件里的 bug 修掉」，通常是 5～30 个步骤。

所以 Agent 慢、贵，并不是它笨，而是它在真的干活；它给你的「回复」其实是一份工作日志，不是一段答案。

人工智能导论 · 第 1 讲

这一页解释学生最常见的困惑：「为什么它这么慢，还这么费钱？」

可以现场演示：让它做一件小事，然后展开它的工具调用记录，让学生看到「原来它背后的请求有十几条」。

它的办公桌有多小约 2 分钟

上下文窗口：Agent 的桌面，以及「压缩」

上下文里到底装着什么

  • 系统提示词（它的身份和规矩，你看不见但每轮都在）
  • 工具列表（它能用哪些工具、怎么用）
  • 这几轮所有的对话历史和所有工具输出
  • 你刚发的那句话

它有一个上限

例如 128K token（大约 6～10 万汉字）。听着很多，但一条命令的输出就能吃掉几千——读一个大文件、跑一次测试，桌面立刻满了。

满了怎么办 → 压缩

把前面的对话总结成一段摘要，用它替换掉原来那一大堆内容，然后接着干。

代价：细节丢了。摘要里没写的东西，它就真的再也想不起来。

所以：任务告一段落时手动压缩，比系统在关键时刻自动压缩，丢得少。

由此得到一条最实用的经验

需要留下来的东西，让 AI 写进文件，不要只留在对话里。对话会被压缩、会被丢掉；文件不会。这也是为什么 Agent 最好的用法，永远围绕着一个工作目录。

人工智能导论 · 第 1 讲

这是全课最值钱的一页之一。很多学生用 Agent 用得很痛苦，就是因为把所有东西都堆在对话里。

举个例子：「这个结论你自己记着」——它记不住，压缩一次就没了。「把这个结论写进 notes.md」——它记得住一辈子。

你会用到的四个会话操作约 1.5 分钟

新建 · 恢复 · 分叉 · 压缩

新建 New

换一件不相关的任务 → 一定开新会话。

混在一个会话里干三件事：前面的无关内容会干扰它判断，而且你每轮都在为那些无关内容付钱。

恢复 Resume

关掉电脑，明天接着干，日志还在。

这是 Agent 相对聊天框的一个大优势：任务可以跨天。

分叉 Fork

从当前这一步复制一份，去试另一种方案，原来的对话完全不动。

典型用法：「这个改法我不满意，但我不想丢掉前面聊的东西。」

压缩 Compact

主动让它总结并清空前面的内容，腾出桌面。

典型用法：一个大任务刚做完，准备开始下一个阶段。

会不会用 AI，很大程度上看你会不会管会话。

人工智能导论 · 第 1 讲

如果学生只记住一句话，就记最后那句。

管住 Agent 的两个开关约 2 分钟

计划模式 与 目标模式

计划模式 Plan

先只出方案，绝不动手。你看完它写的完整计划，点「同意」，它才开始改文件。

适合：会动到重要文件的重活。
不合适：你想让它顺手改个错别字。

它管的是「开始之前」。

目标模式 Goal

给一个长期目标，它自己一轮一轮接着做下去，不用你每次催。你中途可以暂停、改目标、或者看它卡在哪。

适合：一次讲不完、要跑很久的大任务。

它管的是「中途不跑丢」。

还有一个：子代理 Subagent

派一个干净的分身去干一件独立的事（查资料、跑一遍测试、审一遍代码），它自己的上下文不污染你的主对话，干完只带回来一个结论。

类比：你不会让同一个人一边写论文、一边跑腿取快递、还一边记着他所有的事。

人工智能导论 · 第 1 讲

强调「一个管开始前，一个管中途」这个对照，学生好记。

子代理是进阶内容，一句带过，知道有这个东西就行。

第三部分

Agent 模式（预设）

同一个 Agent，给它装不同的工具，就是不同的「模式」

过渡。

四种出厂模式约 1.5 分钟

预设 = 给这个会话装什么工具、什么脾气、什么规矩

模式它有什么什么时候用
标准 standard 全套：读写文件、终端、搜索、技能、计划、目标、子代理、工作流 默认就用它，九成任务够用
极简 minimal 只有两个工具：持久终端 + 文件编辑器 看明白「Agent 到底靠什么活着」；也是最省的模式
PTC 标准模式的能力，但让模型写一段程序来一次性组合很多步操作 步骤很多、又很重复的活（批量处理一堆文件）
创造 cordis 标准模式的能力 + 运行时自省 + 改造自己的能力 进阶：想自己写一个新模式 / 新插件

再加两个会话级开关：计划模式 Plan（动手前先给你看方案）、目标模式 Goal（给个长期目标自己干）。

人工智能导论 · 第 1 讲

DeepSeek Harness 出厂这四个预设：标准、极简、PTC、创造。第 2 次课装好之后会亲眼看到这个选择器。

一个反直觉的结论约 1.5 分钟

为什么必须先玩「极简模式」

只有两个工具，却几乎什么都能干

因为终端本身就是万能工具：能读文件、能写文件、能装东西、能跑代码、能上网。

给它 bash，就等于给了它一双手；给它编辑器，就等于给了它一支笔。

工具越多 ≠ 越强

工具越多，模型越容易选错、越容易在一个小问题上乱试十种办法。多出来的工具，同时也多出了出错的面。

极简模式是最干净的「教学显微镜」

它干了什么，一眼就能看全：读文件、跑命令、看结果、再跑。Agent 的全部秘密就在这几步里。

一句话：Agent 的能力不是来自「很多按钮」，而是来自「一个循环 + 一双能执行命令的手」。

人工智能导论 · 第 1 讲

推荐第 3 次课的实操，第一个任务就用极简模式跑，学生的震撼感最强——「就这俩工具，它居然把贪吃蛇写出来了」。

第四部分 · 本讲核心

Loop Engineering

模型的智力是买来的；循环是你设计的

提醒学生：这一部分是今天最抽象、也最值钱的一块。听不懂没关系，记住最后一页那句话。

Agent Loop 解剖约 2.5 分钟

Agent 的全部秘密，就是这五步转圈

1 组装上下文系统提示词 + 工具表 + 历史
→
2 请求模型一次 API 调用
→
3 模型回答给答案？还是要调工具？
→
4 执行工具真去读文件 / 跑命令
（常常要人批准）
→
5 结果写回日志变成下一步的上下文
↩ 回到第 ① 步，重新请求模型 —— 一直转到第 ③ 步它不再要工具为止

关键点 1：模型是「无状态」的

它不记得上一轮。是循环每次都把完整历史重新递给它。所以「记忆」其实住在循环里，不住在模型里。

关键点 2：第 ④ 步才是真本事

模型只会「说要读文件」。真的去读、并把真结果喂回去的，是循环。没有第 ④ 步，它还是那个只会打字的模型。

人工智能导论 · 第 1 讲

建议在这里配一个现场演示：让它做一件两秒能干完的事，然后打开它的步骤记录，指给学生看「① 它先列了目录 → ② 读了文件 → ③ 跑了命令 → ④ 又读了一次」。

如果只能记住一页，记住这一页。

Loop Engineering 的全部内容约 2.5 分钟

这个循环里，真正难的是这四个问题

1上下文里放什么？

系统提示词怎么写？给它几个工具？历史要不要截断？
放多了它糊涂，放少了它瞎猜。

2怎么防止它跑偏？

什么时候该打断它？哪些操作必须先问过你？什么时候该压缩？
权力给太少它干不动，给太多它敢删你的库。

3什么时候该停？

怎么判断任务成功了？死循环怎么发现？钱花超了怎么办？
不会停的循环，就是一个烧钱的循环。

4出错了怎么办？

重试？换模型？还是把真实的报错原样喂回去让它自己修？
这一步的设计，直接决定它「能不能自己修好」。

模型的能力是别人训练好的，你改不了；这四件事，每一件都是你能设计的。把循环设计好，就叫 Loop Engineering。

人工智能导论 · 第 1 讲

讲第 4 条的时候可以举个反例：有的工具只把「命令失败了」告诉模型，不把报错原文给它——那模型只能靠猜。而把完整报错喂回去的，它往往一次就改对了。

最重要的那条原则约 1.5 分钟

为什么 Agent 比「复制粘贴给聊天框」强那么多

让模型每一步都能看到上一步的真实结果。
不是你的转述，是原始的文件内容、原始的报错、原始的测试输出。

聊天框里

你复制代码 → 它猜 → 给你一段代码 → 你粘贴 → 跑 → 又报错 → 你再复制报错……
每一轮都要你搬一次，而且你搬的时候会丢信息。

Agent 里

它自己打开文件 → 自己跑 → 自己看到完整报错 → 自己改 → 自己再跑。
信息一步都没丢，而且不用你搬。

所以：把「能自己验证」的任务交给 Agent，收益最大；把「只能靠你判断」的任务交给 Agent，收益最小。

人工智能导论 · 第 1 讲

这一页回答「凭什么值得为 Agent 花更多钱」。

落到学生的实际场景：写代码、跑实验、整理数据——能被跑起来验证的，都特别适合 Agent。写论文的「观点」不行，因为它没法验证。

第五部分

Harness

模型要变成产品，中间缺的正是它

过渡。

Harness 是什么约 2 分钟

Harness：把模型包装成「能干活的产品」的那一整套工程

harness 原意是马具——把一匹马拉上车的那整套东西：笼头、缰绳、鞍、车辕。马有力量，但没有马具，你既坐不上去，也控制不了方向。

模型适配

把各家五花八门的 API（DeepSeek / Claude / GPT）统一成一种内部格式

Agent 循环

刚刚讲的那五步转圈，就是它实现的

工具与执行

读写文件、跑终端、搜索、跑代码——以及怎么安全地执行

沙箱与审批

哪些能碰、哪些先问你、哪些一律禁止

会话与日志

把每一步存下来：能恢复、能分叉、能追责

上下文管理

什么时候截断、什么时候压缩、压缩丢什么

界面

终端里的、还是网页里的；怎么让你看见它正在干什么

配置与插件

怎么换模型、怎么加自己的工具、怎么改它的规矩

类比：模型是发动机；harness 是底盘、变速箱、方向盘、仪表盘和刹车。发动机再好，没有底盘你开不走；刹车不好，你不敢踩油门。

人工智能导论 · 第 1 讲

第六部分

六个必须记住的术语

接下来三次课的每一次报错，都出在这六个词上

过渡。强调：这部分是最实用、最枯燥、但必须听懂的部分。

三要素约 2.5 分钟

base_url + API Key + model id

任何一个软件要接上任何一个模型，都必须回答三个问题。三个全对才通，错一个就报错。

base_url 送到哪

请求发给哪台服务器。
相当于去哪家店买。

https://api.deepseek.com
https://你的中转站域名

API Key 你是谁

一串 sk- 开头的密钥。
它就是你的钱——服务器凭它从你账上扣费。

泄露 = 别人花你的钱。
不贴群里、不传 GitHub、不发截图。

model id 要哪个

同一个地址下往往有很多款模型，靠名字区分。
相当于买哪个型号。

deepseek-flash
deepseek-v4-pro

报错怎么查：401 → Key 错  ·  402 → 余额不足  ·  404 / Model Not Exist → model id 写错  ·  连不上 / 超时 / 返回一个网页 → base_url 错。

人工智能导论 · 第 1 讲

这一页要放慢。学生后面每次配工具都要用这三样。

现场最好打开 DeepSeek 的模型配置页，指着三个输入框讲一遍。

两个往年踩过的坑，今年必须讲清：

  • base_url 别凭印象加 /v1。网上很多老教程写 https://api.deepseek.com/v1，而官方现在的文档一律写不带 /v1 的 https://api.deepseek.com。照着官方文档抄，不要照着博客抄。
  • 模型名变了。deepseek-chat 和 deepseek-reasoner 这两个 2025 年到处都在用的名字，已经在 2026 年 7 月 24 日停止使用。现在只有 deepseek-flash 和 deepseek-v4-pro。

这一条可以顺势点一句：AI 这个领域，半年前的文章就可能已经失效——包括老师发给你的和我今天讲的。

协议：同一个聊天，三种信封约 2.5 分钟

response 协议：为什么 Key 和地址都对，还是报错

「回答我这句话」这件事，不同公司用的信封格式不一样，连网址路径都不一样。

协议请求路径谁在用
Chat Completions
最通用		 POST {base_url}/chat/completions 几乎所有模型和中转站都支持。遇到不兼容，先试它。
Responses POST {base_url}/responses OpenAI 的新格式。Codex 只认它——旧的 Chat 格式已经不再支持
Messages POST {base_url}/messages Anthropic 的格式，Claude Code 用它

关键理解：协议只是信封，跟背后是哪家的模型没关系。同一个模型能被包成三种信封 —— 而 DeepSeek 官方三种都提供，一个 Key 就够：

# OpenAI 格式（最通用）      https://api.deepseek.com
# Responses（Codex）        https://api.deepseek.com   ← 同地址，路径不同
# Anthropic（Claude Code）  https://api.deepseek.com/anthropic

所以：一个中转站说「支持 Claude Code」，意思是它提供了 Anthropic 格式的端点；说「支持 Codex」，意思是提供了 Responses 格式的端点。新手 90% 的报错，都是 Key / base_url / 协议这三样没对齐。

人工智能导论 · 第 1 讲

不要背路径，记住「有三套信封，装错了寄不到」就够了。

最后那块绿色的例子要讲透，因为它推翻了一个流传很广的说法：很多人以为「要用 Claude Code 就必须买中转站」。实际上在 2026 年，DeepSeek 官方自己就把 Anthropic 格式的端点开好了——阿里云百炼、智谱、Kimi、MiniMax、硅基流动、火山方舟也都做了同样的事。

一句话：协议只是信封，信封可以换，里面的模型才是关键。

剩下几个，一句话一个约 2 分钟

你在报错信息里会反复见到它们

token

计费和长度的单位。约 1 个汉字 ≈ 0.6～1 token。
你花的钱 ≈ 上下文长度 × 请求轮数。
所以「少废话、多写文件」是省钱的。

压缩 compaction

桌面快满了 → 把前面的对话总结成一段摘要替换掉。
丢细节。任务告一段落时主动压缩最划算。

流式 streaming

token 一个个吐出来，所以你看到它「边想边打字」。
它不代表更快，只是让你更早看见。

系统提示词 system prompt

你每轮看不见、但它每轮都在读的那段话。
决定了它的身份、规矩，以及「它知道自己有哪些工具」。

沙箱 / 审批 sandbox · approval

因为它能碰你电脑，所以必须有闸门。
默认「要问我」；可以放宽，但别一上来就全自动。

幻觉 hallucination

模型编东西。Agent 时代它的形态变了：
不是编答案，而是编一个不存在的命令或文件名——然后用真实报错纠正它。

人工智能导论 · 第 1 讲

扫讲，每格 15 秒。这些词在第 2、3 次课都会真实出现，到时候再回来对。

幻觉那条是重点：Agent 的真正优势是——它编的东西会立刻被真实世界打脸，然后它自己改。

顺带把账算清楚约 2 分钟

钱是怎么花掉的（以 DeepSeek 为例）

单价（空闲时段）

单位是元 / 百万 tokens：

flash输入命中 0.02
输入未命中 1
输出 4
v4-pro输入命中 0.15
输入未命中 4.5
输出 13.5

换算成人话

1 块钱大约能买 100 万字的输入，或者 20 万字的输出。

所以：学生做实验，几块钱能用很久。真正会烧钱的不是「问问题」，是让 Agent 跑很长的任务。

两个反直觉的点

① 错开高峰：周一至周五 9:00–12:00、14:00–18:00 是高峰，价格翻倍。批量实验放到晚上跑。

② 缓存命中便宜 50 倍：连续对话里重复出现的前缀只按 0.02 元收。所以把稳定的东西放在前面（系统提示词、大段材料）真的有省钱效果。

为什么 Agent 比聊天贵这么多 —— 一句话说清

Agent 的每个步骤，都要把「到目前为止的全部对话」重新发一遍。一个 10 步的任务，前面的内容就被重复计费了 10 次。这就是上一页那条经验的另一半：该压缩就压缩，该开新会话就开新会话，不要把无关的东西堆在一个会话里。

人工智能导论 · 第 1 讲

这条「每个步骤重发全部上下文」是理解 AI 成本的核心，也是理解「为什么要压缩」的核心。讲了这一页，学生就再也不会问「为什么我只说了几句话就花了钱」。

另外可以提一句：并发限制是按账号算的（flash 2500、v4-pro 500），多建几个 Key 不会扩容——这是个常见的误解。

第七部分

一切皆插件

为什么这个设计理念，决定你以后能走多远

过渡。

DSH 的设计准则约 1.5 分钟

内核极小，其他一切都可以换

内核里只有什么

几个抽象服务（会话、工具注册表、提示词组装、模型路由）
+ 一个 Agent 循环插件。

就这些。其余全部是插件。

「其余全部」包括哪些

模型适配器（DeepSeek / Claude / GPT）· 每一个工具 · 会话日志与存储 · 压缩策略 · 沙箱与审批 · 网页界面 · 甚至那个循环本身。全都能换。

扩展方式

在旁边挂一个插件，而不是给内核打补丁。内核永远干净。

卸载即撤销

插件带来的东西，在它被卸下时全部撤回，不留残渣。

所以：选 harness，其实是选生态——你选的不只是今天的功能，而是以后能往哪儿长。

人工智能导论 · 第 1 讲

这是 DeepSeek Harness 的官方设计准则，原文就叫「一切皆插件」。

给一个类比：传统软件像一栋已经盖好的楼，你想加个窗户得砸墙；插件式 harness 像乐高，你想加什么就在旁边插一块。

中转站约 2 分钟

最省钱的一环，也是最容易踩坑的一环

它解决了什么真问题

你只想用 AI，却要面对：没有外币信用卡、各家官网注册麻烦、想对比几个模型要开好几个号……

中转站把这些合成一件事：一个 base_url、一个 Key、支付宝付款，背后随你切模型。

但是：过去「必须用中转站才能让 Claude Code 用上国产模型」——这个理由在 2026 年已经不成立了。DeepSeek 官方就提供了 Anthropic 格式的端点。

必须知道的风险（不是吓唬人）

  • 它在中间——你的每一句对话它都看得见。这不是它「要不要记录」的问题，是架构决定的
  • 可能跑路，余额打水漂
  • 可能超售、偷偷限速、用便宜模型冒充贵模型
  • 可能把你的对话日志拿去卖
  • 境外模型未备案就向境内提供，本身处在监管灰区

国家安全部 2026 年 6 月专门发过「AI 中转站」风险提示，点名了数据留存、模型缩水、植入后门、数据出境四类问题。

用它的五条原则

① 能官方就官方——学生做实验，官方 API 的免费额度/几块钱就够，根本不需要中转站  ② 真要买，小额充值，把它当一次性消费，别当银行  ③ 不放敏感数据（个人信息、未发表的实验数据、别人的代码）  ④ 没有公开退款条款的平台，默认「钱要不回来」  ⑤ 别用别人送的 Key，也别把你的 Key 给别人

实操 A · 第一次调用现场 10 分钟

在你的终端里，跟模型说第一句话

打开终端（macOS：终端；Windows：PowerShell；Linux：任意终端），把下面三行里的 Key 换成你自己的，逐行粘贴回车：

export DS_KEY="sk-把这里换成你自己的Key"

curl https://api.deepseek.com/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DS_KEY" \
  -d '{"model":"deepseek-flash","messages":[{"role":"user","content":"用一句话解释什么是Agent"}]}'

成功的样子

你会看到一大段 JSON，其中 choices[0].message.content 里就是它的回答，usage 里是这次花了多少 token。

失败的四种样子

401 → Key 写错  ·  402 → 余额不足，去充值  ·  400 / Model Not Exist → model id 写错  ·  连不上 → 地址或网络错

Windows PowerShell 里 curl 是别名，如果报错，把 curl 换成 curl.exe。

看到 JSON 之后追问一句：「你平时用的聊天网页，做的就是这件事，只不过它把这段 JSON 排版好看了。」

没跑通的同学不用卡住，记下报错，下节课开头一起解决。
