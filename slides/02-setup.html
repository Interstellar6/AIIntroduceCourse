过渡。

每个工具都有自己的小本子约 2 分钟

它们把三要素写在不同格式的文件里

工具配置文件格式
Claude Code ~/.claude/settings.json JSON，三要素写在 env 块里
Codex ~/.codex/config.toml TOML，供应商写在 [model_providers.xxx] 段里

看出来了吗：格式不一样，要填的东西一模一样——还是 base_url、Key、model id 那三样。
这就是为什么第 1 讲要先把三要素讲清楚。

手改配置文件是什么体验约 2 分钟

能用，但很容易出错

Claude Code

{
  "env": {
    "ANTHROPIC_BASE_URL":
      "https://api.deepseek.com/anthropic",
    "ANTHROPIC_AUTH_TOKEN": "sk-xxxx",
    "ANTHROPIC_MODEL": "deepseek-flash[1m]"
  }
}

Codex

model = "deepseek-flash"
model_provider = "deepseek"

[model_providers.deepseek]
name = "DeepSeek"
base_url = "https://api.deepseek.com"
env_key = "DEEPSEEK_API_KEY"

痛在哪

① 两个文件、两种格式、两组变量名   ② 少一个逗号整个文件就废了   ③ 想从 DeepSeek 换成别家，要再改一遍   ④ 想同时用三个 CLI，每个都要配   ⑤ 改坏了没有「撤销」

第二部分

cc-switch

一个开关面板，替你管住上面那些文件

过渡。

它是什么约 2 分钟

cc-switch：管「供应商配置」的桌面小工具

它做的事

  • 内置几十家供应商的预设，选一个就填好了
  • 你只要补上 Key（和 model id）
  • 点一下 Enable，它就替你改写对应 CLI 的配置文件
  • 支持 Claude Code / Codex / Gemini CLI 等多个工具
  • 所有数据存在自己电脑上（~/.cc-switch/）

它的价值：把「切换」这件事变成一次点击

官方 vs 第三方、便宜模型 vs 强模型、这个月用这家下个月用那家——不用再手改文件。

先说清楚：你可能暂时用不到它

如果你只用 DeepSeek 一家，而且只用一个工具，那 DeepSeek 官方给的配置方式已经足够，不需要 cc-switch。

但只要出现下面任一情况，它立刻变得很值：

  • 你在用好几个 CLI
  • 你想在多家模型之间来回比较
  • 你不想每次换 Key 都去翻配置文件

学会它，是为了以后少踩坑，不是为了今天就非用不可。

人工智能导论 · 第 2 讲

诚实很重要：不要为了讲一个工具而制造需求。先讲清它解决什么问题、什么时候不需要它，学生以后遇到多工具场景自然会想起来。

项目地址：github.com/farion1231/cc-switch，官网 ccswitch.io。提醒一句：官方声明过，任何向你收费、索取登录凭据的「CC Switch」都是假冒的。

安装与使用约 2 分钟

装它、用它，一共四步

安装

# macOS（推荐）
brew tap farion1231/ccswitch
brew install --cask cc-switch

# 或者：去 GitHub Releases 下载
#   macOS → .dmg
#   Windows → .msi / Portable.zip
#   Linux → .deb / .rpm / .AppImage

它是桌面应用，不是 npm 包，别去 npm install cc-switch。

使用

  1. 打开 App → Add Provider
  2. 选内置预设（比如 DeepSeek），或自己填
  3. 补上 API Key，需要时改 model id
  4. 选中它 → 点 Enable
  5. 重启对应的 CLI（Claude Code 支持热切换，不用重启）

回到官方登录：加一个 Official Login 预设，再切回来即可。

它改了什么：Claude Code → ~/.claude/settings.json 的 env 块  ·  Codex → ~/.codex/config.toml  ·  Gemini CLI → ~/.gemini/.env。它自己还留了一份数据库和自动备份在 ~/.cc-switch/。

为什么用它上课约 2 分钟

回到第 1 讲的那几个概念

它是「一切皆插件」的那个 harness

内核极小，模型适配器、工具、压缩策略、界面全是插件，都能换。所以你看到的每一个行为，都能找到它对应的那一块。

它有网页界面，不用背命令

对第一次用 Agent 的同学友好得多。先会用，再去理解终端——这个顺序更适合入门。

它有「模式」可以选择

标准 / 极简 / PTC / 创造。你可以亲手把工具从几十个减到两个，然后看着它照样把事情做完——这是理解 Agent 最快的方式。

它便宜、直连、不用中转站

填一个 DeepSeek Key 就能用。今天全程不碰中转站，安全性最高。

它是一个开源的开发者预览版——会变、会有 bug，但正好能让你看清里面在转什么。

安装约 2 分钟

两步：装 Node，然后一行命令

1装 Node.js

去 nodejs.org 下载 LTS 版本（需要 Node 22 或更新），一路下一步。

# 装完在终端里验证
node -v
npm -v

看到版本号就对了。macOS 有 Homebrew 的话也可以 brew install node。

2启动 DSH

npx @deepseek-ai/dsh web

它会自动下载并运行，然后在浏览器打开：

http://127.0.0.1:3080

想只启动不自动开浏览器，加 --no-open。

重要习惯：先 cd 到你要让它干活的目录，再启动。DSH 会把「启动时所在的目录」当作默认的工作位置。你今天就在这个目录下建一个练习文件夹。

如果 3080 端口被占（比如你之前已经开着一个），DSH 的 Web UI 可能就是你现在这台机器上跑着的那一个。

配置模型约 2 分钟

把 Key 填进去，它就活了

操作路径

  1. 点 设置 → 模型
  2. 找到 DeepSeek 卡片
  3. 把上节课的 API Key 粘进去
  4. 保存

不需要重启，下一次请求就生效。

关于你的 Key，两个细节

① 它是只写的：保存之后，界面只会显示脱敏后的样子，永远不会再把明文显示出来。存在你本机的凭据文件里，不上传。

② 别把 Key 截图发群里问「我这里对不对」——截图等于泄露。要问就描述报错文字。

顺带看一眼这一页的另一个入口：「添加自定义提供方」。这就是第 1 讲说的「填 base_url + 协议 + Key + 模型」，中转站、公司网关都从这里接。

人工智能导论 · 第 2 讲

「只写」这个设计值得点一句：这是专业工具的做法——能少存一次明文就少存一次。

选择工作区约 1.5 分钟

不选工作区，输入框是灰的

为什么必须先选一个目录

因为 Agent 要能读写文件。它得先知道「我能碰哪里」——这个目录就是它的活动范围，也是它的安全边界。

这正好呼应第 1 讲的沙箱：Agent 能干活的区域，是被明确划出来的。

操作

  1. 点 选择工作区
  2. 添加你刚才 cd 进去的那个目录（例如 ~/ai-lab）
  3. 选中它
  4. 输入框亮了，可以开始了

一条要养成的习惯

永远让 Agent 在一个专门的练习目录里干活，别一上来就指向你的论文文件夹或代码仓库。等你熟悉它的脾气了，再逐步放开。

卡住了看这里约 2 分钟

今天最可能遇到的六个问题

现象原因与处理
node -v 报「找不到命令」Node 没装成功，或装完没重开终端。先关掉终端窗口再重开。
npx 卡住不动第一次要下载，等 1–2 分钟。还不行就是网络问题，换个网络或设代理。
浏览器打不开 127.0.0.1:3080端口被占用（可能你已经开着一个），或者 DSH 进程退出了——回终端看它打印了什么。
401 / MISSING_CREDENTIALKey 没填、填错、或前后带了空格。回「设置 → 模型」重新粘一次。
402 / 余额不足去 platform.deepseek.com 充值。
UNKNOWN_MODEL选了不存在的模型。回模型选择器换一个可用的。

通用心法：报错信息里几乎总是写着答案。先读一遍，再去搜，最后才问人。
