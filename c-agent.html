模型与 Agent

上一页说到，光靠「凭感觉让 AI 写」，你没法为结果负责。原因在于大多数人只用了 AI 能力的一小部分——这一页就讲清楚那个被漏掉的部分是什么。理解了这个差别，后面所有的工具、配置、注意事项就都能串起来了。

两种用法

绝大多数人对 AI 的使用，停在下面左边这一列。

用法一：把它当搜索引擎

  • 问它问题，复制答案
  • 它说错了，你重新问一遍
  • 它说「你可以这样删除文件」，然后你自己去删
  • 用完关掉网页，一切归零

→ 你在搬运信息。

用法二：把它当同事

  • 给它一个目标，不是一句话
  • 它自己去读文件、跑命令、看报错
  • 报错了它自己改，改完自己再试一次
  • 干完给你，还留有完整记录

→ 你在派活。

差别不在于模型有多聪明，而在于它能不能动手，以及动完手之后能不能看到后果。

举个具体例子。你在聊天框里说「帮我看看我这段代码为什么报错」，实际的流程是：你复制代码 → 它猜 → 给你一段新代码 → 你粘贴 → 跑 → 又报错 → 你再复制报错……来回好几轮。
而在 Agent 里，它自己打开文件、自己跑一遍、自己看到完整的报错、自己改、自己再跑。

模型是什么

先把「模型」这个词的定义收窄。一个语言模型的全部工作就是：

输入一段文字  →  算出下一个字  →  再算下一个字  →  ……  →  停下

这就是一次 API 调用的全部内容。没有别的。

从这句话能推出三件很重要的事：

它没有记忆

你关掉网页，它连你是谁都不知道。
「它记得我」这件事，是软件在外面替它把对话存下来、每次重新念给它听的。

它没有手

它唯一的输出是文字。
它说「我已经帮你删掉那个文件了」——其实它什么都没删。它在骗你，而且不是故意的。

它是一次性的

你问 → 它答 → 这次调用结束。
想让它在中间停下来、看一眼结果、再决定下一步？它自己做不到。

💡
一句话记住 模型是一台只会打字的机器，只不过它打出来的字经常是对的。

Agent 是什么

Agent 不是一个更强的模型。它是给这个模型配上了一套外部机制：

Agent = 模型 + 循环 + 工具 + 持久日志

1 循环

模型说完不算完。如果它说「我要读 a.py」，程序真的去读，把内容塞回去，再问它一次。转很多圈，直到它不再需要工具。

下一页会专门讲这个循环。

2 工具

读写文件、执行终端命令、上网搜索、跑代码、派分身。

模型只负责「说要用哪个」，真正执行的是外面的程序。

3 日志

每一步都写进一份只追加的记录。所以它可以恢复、可以分叉、可以事后追查它到底干了什么。

4 闸门

因为它能真的动你的电脑，所以必须有沙箱和审批：哪些能碰、哪些要先问你。

⚠️
「闸门」不是可有可无的附属品 它是 Agent 能存在的前提。一个没有权限控制的 Agent 不叫 Agent，叫定时炸弹。后面你会在每个工具里见到它——Codex 里叫 sandbox_mode 和 approval_policy，DSH 里就是一个弹窗。

加上这四样之后，它就从「回答问题的」变成了「干活的」。

能不能碰你电脑不能能（读文件、跑命令、上网）

看最后两行。Agent 的代价是「更贵」和「真的会闯祸」——这正好解释了为什么它一定要有审批机制，也解释了为什么购买 API 那一页要教你怎么看账单。

那你到底该用哪个

Agent 不是「更高级的用法」。它是一个有成本的工具，用错地方只会更慢更贵。

出现下面任何一条，你才需要 Agent：

① 任务要碰你的文件

改代码、整理几十个 Excel、批量重命名、跑你的实验脚本。

② 任务需要多步试探

「跑一下，报错了，改一改，再跑」——需要它自己看到结果再决定下一步。

③ 中间过程太多，你不想搬运

几十个文件的输出、几万行日志，你不可能复制粘贴给聊天框。

🤔
一条都不满足？那就别折腾 「解释一下这个概念」「帮我想三个标题」——用聊天网页更快、更便宜。
装工具是有成本的：要花钱、要配置、它还可能改错你的文件。工具是给「干活」用的，不是给「聊天」用的。

这条建议不是客套。很多人装了一堆 Agent，最后还是回去用聊天框——因为他们的任务本来就不需要 Agent，只是听说「这个更强」。

把这个理解用到你自己身上

作为一个学生，你的任务里哪些符合上面那三条？

  • 整理数据、跑复现实验、管理参考文献 —— 非常符合。要碰文件、要多步试探、中间输出很多。
  • 学会用终端、读懂一篇论文 —— 也能用，但价值不一样：它是陪练和助教，不是干活的。
  • 「帮我写一段论文」 —— 不太符合。写作的中间结果没法自动验证，最终判断只能是你。

记住这条判断标准：能被跑起来验证的任务，交给 Agent 收益最大；只能靠你判断的任务，它帮不上多少忙。
