Agent 循环

上一页讲的是「循环里的每一步怎么组织」。这一页退后一步，讲循环本身——它为什么长这样、里面真正难的是什么。这是整套材料里最抽象、也最值钱的一部分：看懂了它，你就能理解为什么同样是 AI，装在不同软件里的能力差别会那么大。

Agent 的全部秘密，就是这五步在转圈

就这五步。整个 Agent 的所有行为，都是这五步转了很多圈的结果。上一页那三种范式（ReAct、Plan-and-Solve、Reflection），说的就是这五步里第 ③ 步该怎么组织。

两个关键点

关键点一：模型是无状态的，记忆住在循环里

回到上一页说的「模型没有记忆」。那 Agent 为什么能记住前面做过什么？

因为循环每次都把完整的历史重新递给它。第 ① 步做的就是这个：把系统提示词、工具列表、所有历史对话和工具输出打包成一大段文字，一起发过去。

所以「记忆」这个能力，其实不属于模型，属于循环。这也解释了为什么上下文会满、为什么需要压缩——因为每次都要把全部历史重发一遍。

关键点二：第 ④ 步才是真本事

模型只会「说要读那个文件」。真的去读、把真实内容喂回去的，是循环。

没有第 ④ 步：  它说「你应该先看看 config.py 里写了什么」   ← 还是那个只会打字的模型
有第 ④ 步：    它自己打开 config.py，看到真实内容，发现端口写错了，改掉  ← 这才是 Agent
🔑
如果这份材料你只记住一个东西 记住这个循环。它是所有 Agent 工具的共同骨架——DSH、Claude Code、Codex，界面完全不一样，里面转的都是这五步。

Loop Engineering：这个循环里真正难的四件事

「写一个循环」本身不难，几十行代码就能写。难的是下面四件事——把它们合起来，就叫 Loop Engineering（循环工程）。

1 上下文里放什么？

系统提示词怎么写？给它几个工具？历史要不要截断？

放多了它糊涂，放少了它瞎猜。

2 怎么防止它跑偏？

什么时候该打断它？哪些操作必须先问过你？什么时候该压缩？

权力给太少它干不动，给太多它敢删你的库。

3 什么时候该停？

怎么判断任务成功了？死循环怎么发现？钱花超了怎么办？

不会停的循环，就是一个烧钱的循环。

4 出错了怎么办？

重试？换模型？还是把真实的报错原样喂回去让它自己修？

这一步的设计，直接决定它「能不能自己修好」。

第 4 条值得展开讲

有些工具只把「命令失败了」这句话告诉模型，不把报错原文给它。这时候模型只能靠猜。
而把完整报错喂回去的工具，它往往一次就改对了。

反过来，这也告诉你作为使用者该怎么做：当它卡住的时候，把完整报错原样贴回去，不要只说「还是不行」——那句话里没有任何它能用的信息。这一点在练习任务那一页还会再强调一次。

最重要的一条原则

让模型每一步都能看到上一步的真实结果。

不是你的转述，是原始的文件内容、原始的报错、原始的测试输出。

在聊天框里

你复制代码 → 它猜 → 给你一段新代码 → 你粘贴 → 跑 → 又报错 → 你再复制报错……

每一轮都要你搬一次，而且你搬的时候会丢信息。

在 Agent 里

它自己打开文件 → 自己跑 → 自己看到完整报错 → 自己改 → 自己再跑。

信息一步都没丢，而且不用你搬。

🎯
所以：把「能自己验证」的任务交给 Agent，收益最大；把「只能靠你判断」的任务交给 Agent，收益最小。
写代码、跑实验、整理数据——能被跑起来验证的，都特别适合。而「帮我想一个论文观点」就不行，因为它没法验证。

所以：模型是买来的，循环是设计出来的

模型的智力是别人训练好的，你只能选，不能改。但这个循环里的每一个决策——放什么进上下文、给多少权力、什么时候停、怎么处理错误——全都是可以设计的。

这就是为什么 2024 到 2026 年出现了这么多 Agent 工具：它们常常用的是同一个模型，差别几乎全在循环和它外面那一层。

🧭
这改变了一个很常见的提问方式 以后选工具的时候，不要只问「它用哪个模型」。要问：它的循环是怎么转的？它给模型看的上下文里有什么？它允许模型动哪些东西？出错时它怎么告诉模型？
这些问题的答案，比模型名字更能预测它好不好用。

这套循环在哪儿能看到

这一页讲的东西听起来像原理，但它其实是你在界面上天天见到的：

界面上的东西对应循环的哪一步
「正在读取文件…」「正在运行命令…」第 ④ 步：执行工具
每一步可展开的工具调用记录第 ③④⑤ 步的全过程
「是否允许执行这条命令？」第 ④ 步之前的闸门
聊到一半提示「正在压缩上下文」第 ① 步：重新组装上下文
它自己发现报错并改好了第 ⑤ 步把真实结果写回去，下一圈第 ③ 步做出新决定

装好工具之后，建议你故意展开一次它的步骤记录看一遍。看着这五步真实地转起来，比读十页文档都管用。
