报错对照表

这些错误码来自模型服务。记住它们，你就能自己诊断绝大多数问题。

报错含义怎么办
400请求格式不对通常是模型名写错了，或者请求体格式有问题
401认证失败Key 错了、多了空格，或者放错了变量名
402余额不足去充值
404 / 连不上地址不对检查 base_url，看有没有多写或少写 /v1
429请求太快 / 并发超限等一会儿再试；正常学习用量碰不到
MISSING_CREDENTIAL没找到凭据Key 没填或者没保存
UNKNOWN_MODEL选了不存在的模型回模型选择器换一个已配置的
🔍
最有用的一条心法 报错信息里几乎总是写着答案。先完整读一遍，再去搜，最后才问人。
还有一个进阶用法：把报错直接粘给已经装好的 AI 工具，让它自己诊断。它能看到你的实际情况，往往比搜出来的答案更准。

按步骤排错

命令找不到（command not found / 不是内部或外部命令）

  • 最常见原因：装完之后没重开终端。关掉所有终端窗口，重新开一个
  • 确认上一步真的装成功了（比如 node -v、claude --version 能不能打印版本）
  • Windows 上，如果安装时没勾「Add to PATH」，需要重新运行安装包并勾上

安装包下载很慢或者超时

  • 换国内 npm 镜像：npm config set registry https://registry.npmmirror.com
  • 换个网络环境试试
  • npx 第一次运行要下载，等 1–2 分钟是正常的

浏览器打不开本地地址

  • 回到终端看：启动它的那个窗口还开着吗？关掉它服务就停了
  • 端口可能被占用，看终端实际打印出来的地址
  • 手动在地址栏输入完整地址（http://127.0.0.1:3080）

AI 说「已完成」但实际什么都没做

这是最常见也最容易被忽略的一条。模型唯一的输出就是文字，它写的「已完成」也只是一串文字。永远去实际检查结果——文件改了没有、命令跑通了没有。

它聊到后面变笨、忘事

上下文满了，触发了压缩，细节被总结掉了。解决办法：任务告一段落就开新会话，把重要结论写进文件带走。

它反复在同一个错误上打转

你给它的信息不够。别说「还是不行」——把完整的报错原文贴回去。它需要看到真实的结果才能改对。

② 命令换行用反引号 `，不是反斜杠 \

Git 常用命令（两个系统完全一样）

# ---- 一次性配置（只做一次）----
git config --global user.name  "你的名字"
git config --global user.email "你的邮箱"

# ---- 最常用的五个 ----
git init                     # 把当前文件夹变成 Git 仓库
git status                   # 现在有哪些改动还没提交
git add .                    # 把改动放进暂存区
git commit -m "说明这次改了什么"   # 提交，留下一个记录点
git log --oneline            # 看提交历史

# ---- 反悔用的（这才是 Git 的价值）----
git diff                     # 我到底改了什么
git restore 文件名            # 把某个文件恢复到上次提交的样子
git restore --staged 文件名    # 从暂存区拿出来（改动还在）
git log --oneline --graph    # 看分支图形
🧯
最该记住的一条 git restore 文件名 能把你改坏的文件退回上一次提交。这是新手最需要的一根救命绳——git status 在提示里也会告诉你这条命令怎么写，照着抄就行。
⚠️
两个新手最容易踩的坑 ① 第一次提交前要先配 user.name 和 user.email，不然会报错。
② 不要把 Git 和 GitHub 搞混。git init / commit 全在你本机完成，不联网、不需要账号；只有 push 到 GitHub 才需要。

术语表

按「你会听到它的场景」分组。

基本概念

词意思
模型输入文字、输出文字的一段程序。没有记忆、不能碰你的文件，一次调用就结束
Agent模型 + 循环 + 工具 + 持久日志。能把事情真的做完，而不只是告诉你该怎么做
Agent 循环组装上下文 → 请求模型 → 模型要工具 → 执行工具 → 结果写回 → 再请求。转很多圈，直到模型不再要工具
Harness把模型包装成能干活的产品的那一整套工程。模型是发动机，harness 是底盘、方向盘和刹车
预设 / 模式给一个会话装哪些工具、什么规矩。比如「标准模式」给全套工具，「极简模式」只给两个
轮次 / 步骤轮次 = 你发一句话后它一直干到停下；步骤 = 一次模型请求加上它引发的工具执行
子代理派一个干净的「分身」去干独立的事，不污染你主对话的上下文

上下文与成本

词意思
token计费和长度的单位。约 1 个汉字 ≈ 0.6–1 token
上下文窗口模型一次能「同时看到」的全部文字，有上限
压缩快满了就把前面的对话总结成一段摘要替换掉。代价是丢细节
缓存命中重复出现的内容只按很低的价收费，便宜 50 倍
流式输出token 一个个吐出来，所以你看到它「边想边打字」。不代表更快，只是更早看见

安全与权限

词意思
沙箱它能碰哪些目录、哪些命令
审批哪些操作必须先问过你
系统提示词你看不见、但它每一轮都在读的那段话。决定了它的身份和规矩
幻觉模型编东西。在 Agent 里它的形态是「编一个不存在的命令或文件名」——然后被真实报错纠正

配置相关

词意思
base_url请求发到哪台服务器
API Key你是谁、从谁的账上扣钱。就是你账户里的钱
model id要哪一个模型
协议请求的「信封格式」。有 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 三种
中转站在用户和模型厂商之间的第三方代理。一个地址、一个 Key 调用多家模型。你的对话内容它会看到
