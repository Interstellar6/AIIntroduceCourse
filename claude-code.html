Claude Code

Anthropic 出的 Agent，在读写代码这件事上做得最成熟。它本来要用 Anthropic 的账号，但 DeepSeek 官方提供了兼容接口——所以你可以用 DeepSeek 的 Key 来驱动它，不需要另外买账号。它既有终端版，也有图形界面版，这一页两个都讲。

当前显示的是 macOS / LinuxWindows 的命令

先选一个界面

Claude Code 有好几种用法，对这门课来说实际能用的是前两种：

形态能接 DeepSeek 吗说明
终端版（CLI） 能 在终端里敲 claude。功能最全，本页的主要部分
VS Code / Cursor 扩展 能 编辑器里的图形侧边栏。需要额外关掉一个登录提示，见下文
JetBrains 插件 没验证 有官方插件，但本文没有实测过接第三方模型的步骤
桌面 App 不能 官方文档只提供「用 Anthropic 账号登录」这条路，且需要付费订阅，没有接第三方模型的入口

它和 DSH 有什么不同

两个都是 Agent，都能读写文件、跑命令。区别在于使用场景和手感：

DeepSeek HarnessClaude Code
界面浏览器里的网页终端 + 编辑器扩展
适合上手、看明白它在干什么长期写代码、改项目
启动方式一条 npx 命令装一次，之后敲 claude

建议两个都装。你会发现同一个模型放进不同的工具里，干活的风格是不一样的——这正是「harness 决定它能干多少活」的意思。

安装（终端版）

推荐：官方安装脚本

curl -fsSL https://claude.ai/install.sh | bash

装的是原生程序，不需要 Node.js，而且会自动在后台更新。

或者用 Homebrew

brew install --cask claude-code

用 Homebrew 装的话不会自动更新，需要偶尔手动跑 brew upgrade --cask claude-code。

或者用 npm

npm install -g @anthropic-ai/claude-code

这条路要求 Node 22 或更新。不要用 sudo npm install -g——官方明确警告过，会造成权限问题和安全风险。

推荐：官方安装脚本

在 PowerShell 里运行：

irm https://claude.ai/install.ps1 | iex

或者用 winget

winget install Anthropic.ClaudeCode

或者用 npm

npm install -g @anthropic-ai/claude-code

要求 Node 22 或更新。不要用管理员权限装。

⚠️
Windows 用户额外提醒 按 DeepSeek 官方文档，Windows 上还需要装 Git for Windows。另外 Claude Code 在 Windows 上的体验不如 macOS / Linux 顺滑；如果你卡在装不上，可以先用 Codex（下一页），它对 Windows 的原生支持更好。也可以考虑用 WSL。

验证安装

claude --version

打印出版本号就成功了。还有一个很有用的自检命令：

claude doctor

它会检查安装是否健康、配置文件有没有写错。配置完之后先跑一遍这个，比等报错要省事得多。

接上 DeepSeek

下面这几行是 DeepSeek 官方文档给出的配置，不是我们自己凑的。核心思路是：把 Claude Code 的请求地址，从 Anthropic 换成 DeepSeek 的兼容端点。

export ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic
export ANTHROPIC_AUTH_TOKEN="sk-把这里换成你的Key"
export ANTHROPIC_MODEL=deepseek-flash[1m]
export ANTHROPIC_DEFAULT_OPUS_MODEL=deepseek-flash[1m]
export ANTHROPIC_DEFAULT_SONNET_MODEL=deepseek-flash[1m]
export ANTHROPIC_DEFAULT_HAIKU_MODEL=deepseek-flash
export CLAUDE_CODE_SUBAGENT_MODEL=deepseek-flash
export CLAUDE_CODE_EFFORT_LEVEL=max
export CLAUDE_CODE_AUTO_COMPACT_WINDOW=786432
$env:ANTHROPIC_BASE_URL="https://api.deepseek.com/anthropic"
$env:ANTHROPIC_AUTH_TOKEN="sk-把这里换成你的Key"
$env:ANTHROPIC_MODEL="deepseek-flash[1m]"
$env:ANTHROPIC_DEFAULT_OPUS_MODEL="deepseek-flash[1m]"
$env:ANTHROPIC_DEFAULT_SONNET_MODEL="deepseek-flash[1m]"
$env:ANTHROPIC_DEFAULT_HAIKU_MODEL="deepseek-flash"
$env:CLAUDE_CODE_SUBAGENT_MODEL="deepseek-flash"
$env:CLAUDE_CODE_EFFORT_LEVEL="max"
$env:CLAUDE_CODE_AUTO_COMPACT_WINDOW="786432"

这几行分别在做什么

变量作用
ANTHROPIC_BASE_URL把请求地址换成 DeepSeek 的 Anthropic 兼容端点
ANTHROPIC_AUTH_TOKEN你的 DeepSeek Key（注意不是 API_KEY，见下面的说明）
ANTHROPIC_MODEL默认用哪个模型。[1m] 后缀表示启用 100 万 token 的超长上下文
ANTHROPIC_DEFAULT_*_MODELClaude Code 内部会按任务难度区分「大模型 / 小模型」，这三个把不同档位都指向 DeepSeek
CLAUDE_CODE_SUBAGENT_MODEL它派「分身」去干独立任务时用哪个模型
CLAUDE_CODE_EFFORT_LEVEL思考投入程度，max 是最高
CLAUDE_CODE_AUTO_COMPACT_WINDOW上下文到这个阈值时自动压缩，这里设得比较大，减少中途压缩
🔑
为什么是 AUTH_TOKEN 而不是 API_KEY 这两个变量对应两个不同的请求头：ANTHROPIC_AUTH_TOKEN 会以 Authorization: Bearer ... 发送，ANTHROPIC_API_KEY 会以 x-api-key: ... 发送。放错变量，请求就会带着服务端不认的头发过去，结果是 401。
记不住就记这一条：拿不准时先用 AUTH_TOKEN。这也是官方的建议。

验证它真的接上了

先进入你的练习文件夹，再启动：

cd ~/ai-lab
claude

进去之后输入斜杠命令：

/status

看输出里的 base URL 一行，如果显示的是 api.deepseek.com，就说明接上了。同时也能看到它当前用的是哪个模型。

⏳
这九行只在当前这个终端窗口有效 你把窗口一关，它们就没了，下次开新窗口还得重新贴一遍。
想让它永久生效，见下一节。

让它永久生效

有两个办法，建议先做第一种（理解发生了什么），再用第二种（省事）。

办法一：写进 Claude Code 自己的配置文件

编辑 ~/.claude/settings.json，加上一个 env 块：

{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.deepseek.com/anthropic",
    "ANTHROPIC_AUTH_TOKEN": "sk-你的Key",
    "ANTHROPIC_MODEL": "deepseek-flash[1m]"
  }
}
💡
这个 env 块里的值，优先级高于你在终端里 export 的同名变量。所以如果两边都配了，以文件里的为准。以后改配置改这里就行，不用再管终端。

办法二：用 cc-switch 点按钮

cc-switch 是一个图形界面工具，选好供应商填上 Key，点一下「启用」，它就替你写好上面这个文件。Claude Code 是它支持得最好的一个——改完不用重启就能生效。

图形界面版：VS Code / Cursor 扩展

如果你不想在终端里敲命令，可以在编辑器里用图形界面。官方把它叫做「在 VS Code 里用 Claude Code 的推荐方式」。

它能做的事：在编辑器里直接看 diff、点按钮接受或拒绝改动、把选中的代码行用 @ 引用进对话、把多个对话开成不同的标签页、查看历史会话。核心能力和终端版一样，只是操作换成了点击。

1. 安装扩展

在 VS Code 里按 Cmd+Shift+X（Windows 是 Ctrl+Shift+X）打开扩展面板，搜索 Claude Code，点安装。Cursor 和 Windsurf 这类 VS Code 分支也支持。

要求 VS Code 1.94 或更新。装完如果侧边栏没出现，用命令面板跑一次「Developer: Reload Window」。

2. 关键一步：关掉登录提示

🔑
不关这个，扩展会一直让你登录 Anthropic 账号 打开 VS Code 设置（Cmd+, / Ctrl+,），搜索 Claude Code login，勾上 Disable Login Prompt。
或者在设置文件里加上： 
"claudeCode.disableLoginPrompt": true
这是官方文档在「使用第三方提供方」一节里给出的做法。

3. 配置仍然写在原来的地方

扩展和终端版共用同一份配置文件。也就是说，你前面写进 ~/.claude/settings.json 那个 env 块，扩展会自动读到——不需要配第二遍。

{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.deepseek.com/anthropic",
    "ANTHROPIC_AUTH_TOKEN": "sk-你的Key",
    "ANTHROPIC_MODEL": "deepseek-flash[1m]"
  }
}

4. 如果它还是提示登录

最常见的原因是 VS Code 没有继承你终端里的环境变量。官方给了两个解法：

  • 先确认上面那个 Disable Login Prompt 已经勾上
  • 从终端里用 code . 启动 VS Code，这样它会继承你 shell 里的环境变量

最稳的做法还是把配置写进 ~/.claude/settings.json——写进文件就没有继承不继承的问题了。

扩展和终端版的区别

能力终端版VS Code 扩展
斜杠命令全部一部分（输入 / 看有哪些）
检查点 / 回退支持支持，而且有图形按钮
MCP 服务器配置支持支持
! 直接跑 shell支持不支持
Tab 补全支持不支持

两者共享同一份会话历史：在扩展里聊到一半，可以到终端里用 claude --resume 接着聊。

💡
一个容易误会的点 装了扩展不等于装好了终端版。扩展自带一份私有的 CLI 供自己的面板使用，但不会把 claude 命令加进你的 PATH。想在 VS Code 的集成终端里敲 claude，还是要单独按上面的步骤装一次终端版。

试试它

在 ~/ai-lab 里启动 claude，然后随便说点什么，比如：

看一下当前目录里有什么文件，用一段话告诉我这个文件夹是干什么用的。

你会看到它自己执行命令、读文件，然后给你结论——而且过程中会问你「是否允许执行这条命令」。那个询问就是审批机制在工作，不是出错了。

常见问题

它一直让我登录 Claude 账号

说明那九个环境变量没生效。最常见的原因有：粘到了不同的终端窗口、粘的时候漏了几行、或者终端是后开的新窗口而变量是旧窗口里设的。重新在一个窗口里完整粘一遍，然后在同一个窗口里运行 claude。

还有一个更省事的思路：直接把配置写进 ~/.claude/settings.json（上一节的办法一），这样它启动时一定能读到。

401 认证失败

  • Key 复制错了，或者前后有空格
  • 变量名用错了：应该是 ANTHROPIC_AUTH_TOKEN，不是 ANTHROPIC_API_KEY
  • 地址少了 /anthropic 后缀

能启动，但回答很怪 / 报模型错误

检查 ANTHROPIC_MODEL。写成 deepseek-chat 是不行的——那个名字已经在 2026 年 7 月停用了，现在要用 deepseek-flash。

想换回 Claude 官方模型

把上面那些环境变量取消掉（关掉终端窗口重新开一个），它就会回到官方的登录流程。或者用 cc-switch 加一个「Official Login」的预设，在两边自由切换。

这一步做完，你就有了一个能长期陪你写代码的 Agent——终端里一个，编辑器里一个，共用同一份配置。
